## 測定の定義

- 屈曲数: 同一直線上の点を除いた折れ点の数。長さは線分長の合計。
- 最小屈曲数は次の順に探す。端点がグループなら、その子孫ノードは障害物から外す。
  - 0: 向かい合う辺のスパンが港マージン（6 unit）を超えて重なり、その区間の水平線か垂直線が障害物（他ノードと他エッジのラベル）を避け、かつ他 net の線分と交差しない。
  - 1: L 字（どちらの角でも）が障害物を避ける。
  - 2: Z 字（どちらの向きでも）が障害物を避ける。
  - 見つからなければ「2 以上（下限未検証）」とし、「避けられる」には数えず別列にした。
- `avoidable` は「実屈曲 > 最小屈曲」。`anchored` は書かれたアンカーがあるか。アンカーを無視して最小を求めるので、アンカー付きで avoidable なら「アンカーがその屈曲を生んでいる」。
- tiny jog: 2 つの屈曲に挟まれた線分で 2mm 未満。4mm 未満は `shortJogs` に別掲（現状 0 件）。
- 重なり: 別エッジの同軸（0.5 unit 以内）の線分が 0.5mm 超で重なるもの。同じ net、または同じ港（同じ辺）を共有するものは trunk として別集計。
- hugging: 平行で中心線間隔が 1.5mm 以内、区間が 3mm 超。エッジ同士、描画されたグループ枠、ノード枠が対象。枠線を描かない（stroke なし）グループは `group-frame-undrawn` として集計から外した。

### 例 1: 3-deep-crl の Encoder → Critic 行列（`e:#5 phi->critic`）: 確認

- 経路: `(926.07,397.97) → (813.57,397.97) → (813.57,434.67) → (785.57,434.67)`。屈曲 2、S 字で 36.7 unit（6.5mm）のジョグ。経路長 31.26mm。
- 最小屈曲は 0。phi の y 範囲は 363.97〜431.97、critic の東辺は 398.67〜578.67。重なりは 398.67〜431.97 の 33.3 unit（5.9mm）で、水平の直線が通る（例: y=404.67）。直線なら長さ 24.8mm。
- 原因は書かれたアンカー `toAnchor: "east:0.2"`。0.2 の位置が y=434.67 で、phi の下端 431.97 より 2.7 unit（0.5mm）外にある。ルータはこのアンカー位置まで折れて合わせ、S 字になった。
- `avoidable=true`、`avoidableDueToAnchor=true`。

### 例 2: 3-deep-crl の h_i からのブロック入力とスキップ接続: 一部確認（幹線の共有は出ず、枠との近さは緩い基準で出る）

- `e:#10 h-in->split`: 屈曲 1。最後の 2.49mm（14.1 unit）が横ジョグ。h-in ラベルの x 範囲 1610.68〜1634.68 に、junction `split`（x=1608.55）が 2.6 unit 届かない。ほぼ一直線のところに 1 屈曲が入る。
- 本来の定義（collinear な重なり）では trunk も非 trunk も 0 件。split からは dense への縦線、skip-low への横線、h-in からの線が T 字に出るだけで、線分は重ならない。「幹線を共有」は、junction の net 共有を指した体感だと思われる。
- スキップ線（`e:#15`、`#16`）は、`g:block` の枠から 5.73mm（左辺の縦線、80mm 区間）と 5.73mm（下辺の横線、30mm 区間）、破線の `g:unit` から 4.34mm（59mm 区間）を平行に走る。hugging の 1.5mm 基準には入らず、緩い近接（6mm、20mm 以上）の欄に出る。
- つまり枠に沿って走るのは事実だが、離れは 4〜6mm。物差しとして使うなら「緩い近接」を指標にするのがよい。

### 例 3: 6-deepseek-v4 の Router → routed experts（`e:#18 router->experts`）: 確認

- 経路: `(533,133.5) → (545.76,133.5) → (545.76,99.25) → (554.26,99.25) → (554.26,88.15) → (568.26,88.15)`。屈曲 4、最小屈曲 2（Z 字）。tiny jog が 2 つ（1.50mm と 1.96mm）。
- Router の東辺から 2.25mm 出た直後に上へ折れ、さらに 1.5mm 横、1.96mm 上と階段状に上って `experts` の西辺（`toAnchor: west`）に入る。
- 最小は 2 で、ユーザーの「直線か 1 屈曲」は測定上は成立しなかった。Router の y 範囲（106.5〜160.5）と experts の y 範囲（75.15〜101.15）が重ならず、L 字は 2 つとも障害物に当たる（north へ出る案は `hash-note` ラベルが、south から入る案は `experts-label` が塞ぐ）。ただしラベルは移せるので、ここは「ラベル回避を前提にすると 2」という意味。

## 既存 lint ルールの動き（`lint --geometry`、10 図すべて）

出たもの（すべて info）は次のとおり。経路に関するものは 1 件のみ。

- `geometry/theme-color-use`: 1-nsa
- `geometry/group-empty-area`: 1-nsa（panel_a）、6-deepseek-v4（block、moe）
- `geometry/arrowhead-cramped`: 8-kimi-k2 の `edges[1]`（synth→repo。矢頭の前の直線が 0.08pt）

出なかったもの:

- `geometry/edge-jog`: 例 3 の jog は 1.5mm と 1.96mm（4pt 以上）で、閾値（1pt 未満）に届かない。例 1 の S 字は端スタブ以外の線分が 36.7 unit あり対象外。
- `geometry/edge-on-border`、`geometry/edge-near-border`、`geometry/edge-near-edge`: 10 図とも 0 件。閾値が「ストローク端から端で 1.5pt 以下」と厳しい。私の物差しは中心線 1.5mm（約 4.3pt）以内なので広い。例 2 のスキップ線は枠から 4〜6mm あり、どちらでも拾えない。
- avoidable な屈曲（例 1 の S 字、例 3 の階段）を検出するルールはない。geometry ルールの一覧に「不要な屈曲」「端のずれ（unaligned ends）」に当たる名前のものは見つからなかった。
- 例 2 の「h_i → split」の 2.6 unit のずれも、どのルールにも引っかからない。

3 例すべてが lint を素通りしている。新しい物差しがカバーする範囲は、既存 lint が見ていない領域。

## 誤検出と限界

- 最小屈曲の探索は、サンプリングした位置（辺上 7 点）で直線・L・Z を試す近似。見落としで最小を実際より大きく見積もる側（avoidable が減る）と、アロー余白や港の面制約を考えずに最小を小さく見積もる側（avoidable が増える）の両方がある。
- 8-kimi-k2 の `e:#4`、`#7`、`#10`（S 字、最小 1 の L が通る）は、ルータが意図的に作ったレーン分離や、複数エッジの共有ポート合わせの可能性がある。L 字にするとアローの余白（約 3.5mm）が足りなくなる場合は誤検出。
- 8-kimi-k2 の `e:#1 synth->repo`: 屈曲 2、直線可能、端スタブ 1.06mm、グループ `c_tools` の枠（`plain` で枠線なし）に 0.35mm で沿う。直線が取れるかは `fromAnchor` なしなので本物の avoidable だが、枠は描かれていないので hugging には数えていない。
- 2-gated-attention の `e:#1`、`#3`（split→wq/wv）は、アンカーを書いた 2 屈曲。最小 1 は L 字が通ることによるが、split から出る 0.62mm の最初の線分は分岐幹線の頭で、意図的かもしれない。
- 3-deep-crl の h-in の例は、ラベルのボックスとジャンクションの 2.6 unit のずれ。junction がラベルの箱の外にあるため、本測定では最小を 1 屈曲とした（avoidable には数えない）。
- hugging の「ノード枠」は、エッジが他ノードの枠に 1mm 前後で平行に走る件数。ルータの標準クリアランス（6 unit = 1.06mm）に当たるものが混じる。6-deepseek-v4 の 3 件と 1-nsa の 1 件、10-multi-agent-research の 1 件（自分のノード `decide` の枠に 31mm 沿う）がこれ。10 の `decide->spawn` は、`decide` の下を 1.06mm で 31mm 這う（`own: true`）ので本物の欠陥に近い。
- 6-deepseek-v4 の `csa-kv-k1->csa-sel-s1` と `csa-kv-k3->csa-sel-s2` の平行（0.8mm、8.3mm 区間）は、エッジ同士の hugging 1 件（lint の `edge-near-edge` は未検出）。
- zoom・straight・curve エッジは、直交の屈曲・重なり測定の対象外。
- 枠なしグループ（`variant: plain`）は描画されないので hugging から外した（4-lost-multiturn で 1 件、6-deepseek-v4 で 1 件、8-kimi-k2 で 2 件）。
- trunk 判定は、同じ net または同じ港（同じ辺）の共有。net の連鎖で別の trunk に見えるものは同じ trunk として扱う。
