# #509 v0.17.1 の初稿の評価: 直接 YAML と HTML の下絵から

## 目的

エージェントが Sumi Skill で描く図の、外部のレビューを受ける前の質を測り、次の 2 つの手順を比べる。

- **A（直接）**: `skills/sumi/SKILL.md` どおりに YAML を書く。エージェント自身の確認（描画して見る、lint）は行うが、サブエージェントによるレビューは行わない。
- **B（HTML の下絵から）**: Sumi の語彙に限った HTML/CSS の下絵を先に作り、PNG にして見て整えたあと、それを原図として YAML で再現する。

## 条件

- エージェント: Claude Opus（新しいコンテキスト。依頼文と本書の手順だけを渡す）。1 依頼 × 1 条件 × 1 回。
- Sumi: 公開版 v0.17.1 のバイナリ（`curl … | sh` で導入したもの）。Skill はリポジトリの `skills/sumi/`。
- テーマ: すべて `sumi`。
- 禁止: `research/` の他のディレクトリ、他の実行のディレクトリ、非公開の図を開かない。著者名・所属・メールアドレスを図に入れない。

## 手順

各実行は `runs/<#>-<slug>/<A|B>/` に次を残す。

- `figure.sumi.yaml`（最終版）、`draft1.sumi.yaml`（最初に描画できた版）
- `draft1.svg` / `draft1.png`、`final.svg` / `final.png`（PNG は `rsvg-convert -w 1600`、地は図の地の色）
- B のみ: `mockup.html`、`mockup.png`（Chrome のヘッドレスでのスクリーンショット）
- `log.md`: 開始・終了時刻、描画の回数、最終の lint の要約（error / warning / info と残した理由）、つまずいた点、Sumi で表せなかったこと

## 採点の基準（図を見る前に決めた）

採点は、手順と描き手を伏せた PNG（final と draft1）で行う。各項目 1〜5。

1. **内容の正しさと網羅**: 依頼の要素がすべてあり、関係（向き・入れ子・共有）が正しい。
2. **読みやすさ**: 置き場所での文字の大きさ、ラベルの長さと折り返し、線と文字の重なりのなさ。
3. **構成**: 主な流れが一目でわかる、視線の向きが一貫している、要素の重要度に応じた大きさと強調、余白の配分。
4. **整列と一貫性**: 同じ役割の要素の大きさ・間隔・形がそろっている、格子に乗っている。
5. **色**: 色数を抑え、強調に意味がある、テーマと調和している。
6. **置き場所への収まり**: 縦横比と大きさが置き場所に合っている、無駄な空白や縮小がない。

総合: 「そのまま使える」「少し直せば使える」「使えない」の 3 段階。

あわせて、時間、描画の回数、lint の warning の数を比べる。
