# #538 結果: v0.18.0 の Skill で #509 の依頼を描き直す

手順と条件は [README.md](README.md)、各エージェントへの指示は [prompt.md](prompt.md)、手順を明かした採点の生データは [scores.json](scores.json)、伏せた対応は [blind-key.json](blind-key.json)。

## 実施

- 2026-11-14、main の 61dc9f49 を固定したワークツリーで、8 依頼を新しい Opus エージェント 1 体ずつに描かせた（条件 S: SKILL.md どおり、サブエージェントのレビューなし）。
- 所要時間（ハーネスの計測）は 2.0〜6.1 分（120〜367 秒）。#509 の 3.7〜6.9 分より短い。
- レイアウト: 依頼 1・4・6・8 は種のレイアウト（encoder-block、train-infer-panels、compare-rows、set-taxonomy）から始めた。2・3・5・7 は合うものがなく一から計画した。
- 下絵: 2・3・4・5・7・8 で作った。1 と 6 は「構成は種のまま」「一方向の比較」として省いた。
- 最終の lint: 8 件ともエラー 0。警告は 2 の 1 件だけ（凡例の破線の見本が短い）。
- 採点: ユーザー 1 人が、依頼ごとに S・#509 の A・#509 の B の 3 枚を、並び順を入れ替え手順を伏せて採点した。基準は #509 と同じ。

## 読み取り

- v0.18.0 の Skill は、サブエージェントのレビューなしで、最終版 8 件中 7 件が「そのまま使える」になった。#509 の下絵の手順（B）より 6 項目すべてで高く、特に整列（+0.75）と収まり（+0.62）が伸びた。
- 唯一 S が勝てなかった依頼 3（パイプライン）は、#509 の A が 1 点上回った。一方向の流れで、下絵の利点が小さい種類という #509 の読み取りと合う。
- 初稿の質が大きく上がった。下絵で構成を先に決め、レイアウトから始めることで、最初の描画から構成が整っている。

## 見つかった課題（エージェントの記録と、レイアウト 22 個を描いた記録から）

- 凡例の見本が `textScale` で大きくならない（破線の見本が短すぎて破線に見えない、見本の箱が文字に近い）。2 件。
- `labelAt: above-left` の見出しと中身の間に約 13mm の隙間が出る。
- 曲線の自己ループ（`route: curve`）が配置の場所を取らず、枠に当たる。
- 集合の楕円の大きさを正確に指定できない（`minWidth` は最小値だけ）。同じ種類の箱の幅をそろえる指定がない。
- 文字を大きくすると円柱が太く見える。
- grid の 2 列にまたがるグループの中身を上の列にそろえられない。
- 1 つの箱からグループ内の 3 つの箱への線が枠に沿う（#512 の再発）。同じ側の入れ子のスキップ接続を別の通り道に分けない。
- lint が見つけないもの: トークン列が列からずれる、線のラベルが線から約 0.5mm、線のラベルが箱の角に重なる、窮屈な矢じり。
- 数式の下付き文字が 5.6pt になり、文字の最小値を満たす手段がない。
- stack の中の要素に `align` を効かせるには 1 要素の `row` で包む必要がある。複数の列にまたがる箱でまっすぐ降ろすには端数のアンカーが要る。
- `color-on-panel` が緑で出て青で出ない（しきい値の境目）。3 集合の Venn で、3 つの重なりの色が集合 C 単独とほぼ同じ。
- Skill: 下絵のガイドが枠の上の見出し（`labelAt: above-left`）を案内していない。`height` をノードに直接書いたときのヒントが `weight` を勧める。matrix の `text: ~` が null と読まれ「Invalid input」だけ。`scripts/preview` の `-o` を入力の後に置けない。

これらは v0.18.1 / v0.19.0 の issue にする。

## 結論

v0.18.0 の変更で、エージェントが Skill どおりに描く図は #509 の A（v0.17 の Skill）から合計で 17.6 → 25.2、「そのまま使える」が 2 → 7 件になった。v0.18.0 として公開できる状態にある。
