# Sumi v0.14.0

図を置く場所（2 段組みの全幅・1 段・1 ページ目の概要図・スライドなど）に合わせて図を作るためのリリースです。置き場所の条件（高さの予算、印刷時の最小の文字と線の太さ）を図に書けるようにし、縮小しすぎの判断を縮小率ではなく印刷時の文字の大きさで行うようにしました。あわせて、対応関係を表す斜めの直線と、横から入る入力を持つ主な流れの書き方を加え、Skill を置き場所から形を選ぶ手順に書き直しました。根拠の調査は [research/345-figure-placement](https://github.com/nishide-dev/sumi-diagram/blob/v0.14.0/research/345-figure-placement/README.md)、計画は [#236](https://github.com/nishide-dev/sumi-diagram/issues/236)、実装は milestone「[v0.14.0 — Placement-aware figures](https://github.com/nishide-dev/sumi-diagram/milestone/25)」です。

## 置き場所の条件を図に書く

- **`figure.target`**（[#347](https://github.com/nishide-dev/sumi-diagram/issues/347)）: 任意の項目です。どれも単位付きの長さで書きます。配置や描画は変えず、幾何 lint の判断に使います。
  - `height`: 高さの予算（余白を含む印刷時の高さ）。超えると warning `geometry/exceeds-target-height` を出し、高さの内訳を示します。図を縮めることはしません。Profile の上限（paper 系 220mm）は従来どおり硬い上限です。
  - `minFontSize`: 印刷時の最小の文字の大きさ（4.5pt 以上）。Profile の最小値を上書きします（引き上げも引き下げもできます）。下回る文字は `geometry/text-too-small`（error）です。
  - `minLineWidth`: 印刷時の最小の線の太さ。下回る枠や線を warning `geometry/line-too-thin` で知らせます。線を描かない部品（junction の点など）は対象外です。
  - `figure.target` を書いた図では、info `geometry/placement-usage` が、予約する紙面の面積（Profile の幅 × 印刷時の高さ）、幅の使用率、高さの予算の使用率を示します。同じ置き場所の候補を比べるための量で、縦横比の良し悪しではありません。
  - `sumi catalog` に `targets` の節を追加しました。
- **添字の大きさ**（[#356](https://github.com/nishide-dev/sumi-diagram/issues/356)）: `minFontSize` を書いた図では、数式の添字（基準の 0.7 倍）も印刷時の大きさで判定し、下回れば warning `geometry/script-below-target` をそのラベル（または sublabel）の位置に出します。縮小していない図も対象です（8pt の `$q_1$` は 5.6pt で印刷されます）。
- **縮小しすぎの判断**（#347）: info `geometry/heavy-scaling` は、`figure.fit: scale` で縮めた図の最小の文字（添字と HTML を含む）が、最小値の 120% 以下になったときに出ます。従来の「縮小率 90% 未満」の条件はなくなりました。

## 新しい書き方

- **`route: straight`**（[#349](https://github.com/nishide-dev/sumi-diagram/issues/349)）: structured の edge に指定すると、端点どうしを 1 本の直線（斜めも可）で結びます。二部マッチングのような対応関係に使います。
  - 端点は図形の輪郭との交点です（`tokens` のセルや、凹んだ輪郭、固定の接点を持つ部品にも対応）。`fromAnchor` / `toAnchor` で辺と位置を選べます。
  - 障害物は避けません。ノードやラベルとの重なり、斜めの線どうしの接近は、既存の幾何 lint が位置つきで知らせます。
  - auto の図では `layout/structured-only` です。
- **`centerOn`**（[#350](https://github.com/nishide-dev/sumi-diagram/issues/350)、[#357](https://github.com/nishide-dev/sumi-diagram/issues/357)）: stack / row に `centerOn: <直接の項目>` を書くと、その項目の中心を主な流れの線にそろえ、横（上下・左右）に置いた入力の分の場所を確保します。例: `{stack: {centerOn: decoder, items: [decoder, queries]}}`。
  - 別の段から来る線は、横の入力がある面を避けて入ります。
  - 不正な指定は `layout/invalid-center-on`（error、位置つき）です。

## 診断の改善

- **配置の提案の試行**（[#351](https://github.com/nishide-dev/sumi-diagram/issues/351)）: 幅の超過などで示す「確かめた修正案」を、`props.svg` や共有の `figure.assets`（crop を含む）の画像を含む図でも試すようにしました。試せないときは、その理由を hint に書きます。
- **縮小した図の `geometry/label-overflow`**（#351）: 印刷時の寸法に加え、縮小前（YAML の単位）の寸法も示します。

## Skill

- **置き場所から形を選ぶ手順**（[#348](https://github.com/nishide-dev/sumi-diagram/issues/348)）: 「全幅の図は高さ 90mm 未満」「縮小せずに折り返す」「4 段以上は縦向き」のような、出典のない固定の規則を外しました。
  - 代わりに、置き場所の制約を確かめ、内容から配置の候補をいくつか作り、描いて測り、硬い制約で除き、比べて選び、理由を報告する手順にしました。
  - 幅が足りないときの選択肢（ラベルを短くする・まとめる・詰める・縮小・折り返し・分ける・置き場所を変える）と、それぞれが費やすものを表にしました。
- **内容の点検**（#348）: 描画したあと、最初に作った要素・辺の向き・入出力の一覧を、YAML と印刷時の大きさの PNG の両方で確かめ、配置を磨く前に直す段を加えました。
- 確認として、DETR の概要図を 2 つの置き場所で描かせました。全幅（180mm、7pt 以上）では横 1 段（179 × 50mm）、1 段（88mm、7pt 以上）では U 字（86 × 78mm）になり、どちらも縮小なしでした。

## 互換性

- Figure Schema は任意の追加だけです。CLI のコマンドは変わりません。
- 既存の図の SVG / PDF / PPTX / D2 は、v0.13.0 と同じです（版に関する metadata を除く）。
- 診断の変化:
  - `geometry/heavy-scaling` の出る条件と文言が変わりました（上記）。
  - `figure.target.minFontSize` を書いて縮小した図では、添字の info `geometry/script-too-small` の代わりに warning `geometry/script-below-target` が出ます。
- 固定版 D2 は v0.9.0、同梱フォント・Tabler Icons・Fluent Emoji Flat・Takumi は v0.13.0 と同じです。
- 設計の判断は [docs/design/decisions](https://github.com/nishide-dev/sumi-diagram/tree/v0.14.0/docs/design/decisions) の各ファイル（#347〜#351、#356、#357）を参照してください。

## インストールと更新

```sh
curl -fsSL https://raw.githubusercontent.com/nishide-dev/sumi-diagram/main/install.sh | sh
```

版を固定するときは `SUMI_VERSION=0.14.0` を付けます（README の[インストール](https://github.com/nishide-dev/sumi-diagram/blob/v0.14.0/README.md#install)）。Skill は `npx skills add nishide-dev/sumi-diagram --skill sumi` で更新します。

公開準備は [#361](https://github.com/nishide-dev/sumi-diagram/issues/361) です。今後の計画は [#236](https://github.com/nishide-dev/sumi-diagram/issues/236) で管理します。
