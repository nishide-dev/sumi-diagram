# Sumi v0.4.1

v0.4.0 を典型的な論文図 4 枚で実際に使った結果（[#109](https://github.com/nishide-dev/sumi-diagram/issues/109)、[記録](https://github.com/nishide-dev/sumi-diagram/blob/v0.4.1/research/109-dogfood-v0.4/README.md)）をもとに、不具合・診断・Skill を直したパッチリリースです。新しい機能や書き方は追加していません。

## 不具合の修正

- **PDF と画像方式 PPTX で、数式ラベルの書体が崩れる問題を直しました**（[#112](https://github.com/nishide-dev/sumi-diagram/issues/112)）。
  - `\to` `\leq` `\nabla` `\partial` `\mid` など、STIX Two Text Italic にない記号を含むラベルで起きていました。同じ行の変数などの部分が代わりの書体で描かれ、斜体が失われていました。SVG は正しく描けていました。
  - 原因は、変換エンジン（usvg）の文字の割り当てでした。usvg は 1 行全体を各部分の書体で順に処理するため、ある部分の書体に同じ行のほかの文字がないと、その部分が代わりの書体に置き換わっていました。日本語と数式が混ざるラベルや、`₂` を含む太字の行も同じ原因で崩れていました。
  - 対応するすべての数式コマンドについて、PDF の各部分の書体と位置をテストで確かめています。
- **structured の図で、同じ口に入る辺と出る辺が 1 本の線に束ねられる問題を直しました**（[#113](https://github.com/nishide-dev/sumi-diagram/issues/113)）。
  - `api → worker` と `worker → store` が `api → store` に読めることがありました。
  - 線を共有するのは、同じ口から出る辺どうし、同じ口に入る辺どうし、junction を介した辺に限ります。同じ口を入りと出の両方に使う場合は、辺に沿って口をずらします。
  - **注意**: 入りと出の両方を、`fromAnchor` / `toAnchor` で同じ位置に明示している場合は、ずらせないため `layout/no-route` になります（v0.4.0 では描けていました）。別の位置（例: `west:0.3` と `west:0.7`）を指定してください。
- **矢じりと辺のラベルの見た目を直しました**（[#116](https://github.com/nishide-dev/sumi-diagram/issues/116)）。
  - 分岐や曲がり角の直後に矢じりが来て、丸めた角に重なることがありました。矢じりの前に直線の区間を取る経路を優先します。経路の制約やグループの余白によっては取れない場合があります。丸めた角が矢じりに重ならないことは、描画の段階で保証します。
  - 短い最後の区間で、辺のラベルが手前の線を覆うことがありました。線やグループの枠と重ならない候補の位置を探して置き直します。適当な候補がなければ、元の位置のままです。

## 診断の改善

- 幾何 lint の hint を、配置方式（auto / structured）と profile で出し分けます（[#114](https://github.com/nishide-dev/sumi-diagram/issues/114)）。
  - structured の図に `layout.direction` を勧めません。
  - すでに使っている用紙や、存在しない「より高い用紙」を勧めません。
  - `attach` による重なりには、それに合った直し方を示します。
- `layout/no-route` が、経路を塞いでいる要素（最大 3 つ）を名前と YAML の位置で示します。
- `geometry/label-collision` が、グループの枠線に乗ったラベルも報告します（#116）。新しいコードは追加していません。
  - auto の図でも報告が増える場合があります。たとえばギャラリーの pipeline 例（slides / presentation-16x9）で、警告が 1 件増えました。

## Skill と性能

- Skill を直しました（[#115](https://github.com/nishide-dev/sumi-diagram/issues/115)）。
  - 数式のアクセント（`\hat` など）の代わりの書き方を加えました。
  - auto が縦にも横にも収まらないときの、2 行への折り返しを説明しました。
  - ページからはみ出したときの直し方を、配置方式ごとに書きました。
  - structured のグループ見出しの位置と、`attach` が場所を取らないことを説明しました。
- 組み込みの部品 Registry を 1 度だけ作って使い回すようにし、検査を速くしました（[#106](https://github.com/nishide-dev/sumi-diagram/issues/106)）。

## 互換性

- Figure Schema、CLI、診断のコードと severity は変わりません。ただし上の注意のとおり、同じ口に入りと出の anchor を同じ位置で明示した structured の図は、`layout/no-route` になります。
- auto の図の SVG / PDF / PPTX は、metadata の `sumi-version` が `0.4.1` になる以外、変わりません。
- structured の図は、#113・#116 の修正で経路と辺のラベルの位置が変わることがあります。
  - 同梱の例: `examples/transformer` は分岐の位置、`examples/dit-block` は右側の幹線とラベルの位置が変わりました。
- 数式に記号を含むラベルの PDF / 画像方式 PPTX は、#112 の修正で正しい書体になります（編集可能 PPTX は、もともと部分ごとに書体を指定しています）。そのため、出力のバイト列も変わります。
- structured の経路探索は、密な合成図（100 ノード・146 辺の格子）で約 205ms から約 405ms へ遅くなりました（#113・#116。macOS arm64 での測定）。同梱の例のような図は、数 ms のままです。
- 固定版 D2 は v0.9.0、同梱フォントは BIZ UD Gothic 1.051 と STIX Two 2.13、Tabler Icons は 3.49.0 のままです。
