# Sumi v0.5.0

論文図の段階 B のリリースです。v0.4 で典型的な論文図 4 枚を描いた結果（[#109](https://github.com/nishide-dev/sumi-diagram/issues/109)）、回避策が必要だった点を Figure Schema のフィールドと部品で書けるようにしました。グループの見出しの位置とキャプション、辺のラベルの位置、配置の木をまたぐ整列、fan-in の口の分散、凡例、数式のアクセント、交差の報告を追加しています。計画は [#124](https://github.com/nishide-dev/sumi-diagram/issues/124)（[調査メモ](https://github.com/nishide-dev/sumi-diagram/blob/v0.5.0/docs/research/124-stage-b.md)）、実装は milestone「[v0.5.0 — Paper figures stage B](https://github.com/nishide-dev/sumi-diagram/milestone/12)」です。機能追加のため minor リリースとします。

新しいフィールドを使う図には、`requires: ">=0.5.0"` を書くことを勧めます。古い Sumi で開くと、未知のフィールドの一覧ではなく、`schema/unsatisfied-requires` の 1 件で止まります。

## グループの見出しの位置とキャプション（両方の配置方式）

```yaml
groups:
  - id: train
    label: Training step
    labelAt: top-left                # 見出しの位置（枠の内側）
    caption: (a) one optimisation step   # 枠の下の中央に置く文字
```

- `labelAt` は `top-left` / `top` / `top-right` / `bottom-left` / `bottom` / `bottom-right` のどれかで、見出しは常に枠の内側に置きます（[#127](https://github.com/nishide-dev/sumi-diagram/issues/127)）。
  - 省略時の位置は従来どおりです。structured は上端の中央、auto は左上です。
  - 上から入る辺が見出しを横切る場合、幾何 lint の hint が `labelAt` で移す案を示します。
  - `label` のない group に `labelAt` を書くと、`component/label-at-without-label`（warning）になります。
- `caption` は、枠の外の下に中央揃えで置く文字です。サブ図の「(a) …」に使います（[#130](https://github.com/nishide-dev/sumi-diagram/issues/130)）。
  - 改行と、structured ではラベルの数式も使えます。位置は固定です。
  - キャプションは `<group>-caption` という ID のラベルとして描きます。この ID を自分の要素に使うと `ref/reserved-id` です。
  - structured では、ルータがキャプションを避けて線を引きます。auto では D2/ELK がキャプションを知らないため、group から下へ出る辺がキャプションを横切ることがあります（`geometry/edge-crosses-label` で警告します）。

## 辺のラベルの位置（structured のみ）

```yaml
edges:
  - { from: model, to: loss, label: '$\hat{y}$', labelAt: middle, labelSide: right }
```

- `labelAt` は、ラベルを置く線分です。`start` は最初の線分、`end` は最後の線分、`middle` は最も長い線分です（[#128](https://github.com/nishide-dev/sumi-diagram/issues/128)）。
- `labelSide`（`left` / `right`）は、source から target へ進む向きに対しての左右です。上下・東西で書かないのは、線分の向きはルータが決めるためです。
- 最初の位置が線・矢じり・枠・node・ほかのラベルに当たれば、指定の線分に沿って、指定の側の中で位置をずらします。指定の範囲に空きがなければ元の位置のまま置き、`layout/edge-label-overlap`（warning）で知らせます。反対側やほかの線分には黙って動かしません。
- どちらも書かない辺のラベルは、v0.4.1 の規則のままです。auto の図で書くと `layout/structured-only` です（D2 はこの指定で位置を変えないため）。

## 配置の木をまたぐ整列（structured のみ）

```yaml
figure:
  layout:
    arrange: { … }
    align:
      - { y: [ enc1, cat1 ] }            # 中心を同じ高さに（1 本の水平線）
      - { x: [ head, key ], at: start }  # 左端を揃える
```

- `figure.layout.align` で、別の箱（stack / row）にある node や group を同じ高さ・同じ縦の線に揃えます。U-Net の skip を水平にする、encoder の出力と decoder の入力を揃える、といった使い方です（[#132](https://github.com/nishide-dev/sumi-diagram/issues/132)）。
- 各制約は `y: [ids]` か `x: [ids]` のどちらか一方と、任意の `at: center | start | end` です。
- Sumi は、項目の前後に余白を足すだけで揃えます。`gap: 0` の箱（一体に描くブロック）の中には余白を入れないので、接した箱は接したままです。同じ stack の 2 項目を `y` で揃えるような、構造上できない制約は `layout/unsatisfied-align`（warning）になり、最も近い配置で描きます。
- 誤った ID などは位置付きのエラーです（`layout/unknown-align-item`、`layout/duplicate-align-item`、`layout/invalid-align`）。整列は `sumi render` と `sumi lint --geometry` で解き、`sumi lint` だけでは配置しないので、`layout/unsatisfied-align` は出ません。
- #109 の規模の図（数個の制約）では、整列は 1ms 前後です。制約が非常に多い図では、配置の回数の上限（1,000 回）で止め、`layout/align-search-limit`（warning）を出します（200 node・1,000 制約で約 0.8 秒。Apple M4 Pro での測定）。

## 既定の辺と fan-in の口の分散（structured のみ）

```yaml
figure:
  layout:
    fanIn: spread   # 既定は merge
    arrange: { … }
```

- **anchor のない端が付く辺を、配置の木から決めるようにしました**（[#134](https://github.com/nishide-dev/sumi-diagram/issues/134)。既定で有効）。2 つの要素を分ける箱が stack なら北 / 南、row なら東 / 西の辺から出入りします。ただし、2 つの要素がその向きに実際は離れていない場合（`attach` で添えた要素など）と、分ける箱がない場合は、v0.4 と同じく中心の差で決めます。v0.4 は中心の差だけで決めていたので、stack の下の段で横に遠い箱が東西の辺から出て、相手の横に回り込むことがありました。
- `fanIn: spread` を書くと、別々の要素から同じ口に入る辺を、その辺に並べて別々に入れます。既定の `merge` では、従来どおり 1 本に合流して入ります。
  - 合流させたい場合は `junction` を使います。`fromAnchor` / `toAnchor` を書いた端と junction の端は動かしません。
  - 分散で新しい合流や経路のない辺が生じる場合は、図全体を `merge` の経路に戻します。
  - #109 の図 3 から anchor を除いた版では、`fanIn: spread` で遠回りが 0 本、excess が 1.1mm になりました。合流していた線が別々に引かれるので、交差の点は増えることがあります（同じ図で 6 点）。

## 凡例（`component: legend`、structured のみ）

```yaml
nodes:
  - id: key
    component: legend
    props:
      entries:
        - { edge: { variant: dashed }, label: gradient }
        - { node: { tone: blue }, label: trainable }
```

- 線種や塗りの意味を示す枠を描きます（[#131](https://github.com/nishide-dev/sumi-diagram/issues/131)）。各項目は、見本の線（`edge`: `component`・`variant`）か見本の箱（`node`: `component`・`variant`・`tone`）のどちらか一方と、`label` を持ちます。項目は 1〜20 件です。
- 見本は本物の辺と node として描くので、図の中の同じ部品・variant と同じ線・矢じり・塗りになります。色の値は書かず、Theme が決めます。
- 凡例の `label` は枠の見出しです。`variant: plain` で枠を消せます。
- 凡例は配置の木の項目として置きます。`attach` で置くと `layout/attached-legend` です。図の中に同じ見本の辺や node がない項目は、`lint/unused-legend-entry`（warning）になります。
- 部品の manifest に、描ける配置方式（`engines`）を書けるようにしました。`sumi catalog --json` とギャラリーの部品の表に出ます。凡例は `structured` だけで、auto の図で使うと `layout/structured-only` です。ギャラリーに凡例の見本 4 枚を追加しました。

## 数式のアクセント（structured のみ）

```yaml
label: '$\hat{y}_t$, $\tilde{x}$, $\bar\theta$, $\vec{W}$'
```

- ラベルの数式で、`\hat` `\tilde` `\bar` `\dot` `\ddot` `\vec` を 1 文字（またはギリシャ文字などの 1 コマンド）に付けられます（[#129](https://github.com/nishide-dev/sumi-diagram/issues/129)）。後の `_` / `^` はアクセントの付いた文字に付きます。添字と `\mathrm{…}` の中でも書けます。
- アクセントの位置は Sumi が字形の箱と斜体の傾きから決めます。SVG・PDF・画像方式 PPTX で同じ位置になります。PDF からは、基底の文字と結合文字（`y` U+0302 など）として抽出できます。編集可能 PPTX では結合文字を含むテキストになります（PowerPoint での見た目は未確認です）。
- 幅のあるアクセント（`\widehat`、`\overline` など）、複数文字への付加（`\hat{xy}`）、アクセントの重ねは `component/invalid-math` です。v0.4 では、アクセントはすべてこのエラーでした。

## 交差の報告（structured のみ）

- structured の図で、別々の線が交差する点を `layout/edge-crossing`（info）で知らせます（[#133](https://github.com/nishide-dev/sumi-diagram/issues/133)）。`sumi render` と `sumi lint --geometry` に出ます。
- 共有の幹線は 1 本の線として数え、交差の点ごとに 1 件です。10 件を超える場合は、残りを要約の 1 件にまとめます。メッセージは両側の辺と、点の位置（キャンバスの左上からの mm）を示します。
- hint は直し方（直したい辺を YAML で前に移す、anchor で別の辺から出す、配置を変える）を示します。交差を自動で減らすことはしません。
- info なので、終了コードと `--max-warnings` には影響しません。描画結果も変わりません。

## 新しい診断

| コード | severity | 内容 |
| --- | --- | --- |
| `component/label-at-without-label` | warning | 見出しのない group に `labelAt` がある |
| `ref/reserved-id` | error | キャプション・凡例が使う ID（`<group>-caption`、`<legend>-<n>-label` など）を自分の要素に使った |
| `layout/edge-label-overlap` | warning | `labelAt` / `labelSide` の範囲に空きがなく、ラベルが何かに重なる |
| `layout/unknown-align-item`、`layout/duplicate-align-item`、`layout/invalid-align` | error | `figure.layout.align` の未知の ID、重複、項目が 2 個未満 |
| `layout/unsatisfied-align` | warning | 整列の制約を満たせない（最も近い配置で描く） |
| `layout/align-search-limit` | warning | 制約が多く、整列の探索を上限で止めた |
| `layout/edge-crossing` | info | structured の図で線が交差する |
| `layout/attached-legend` | error | 凡例を `attach` で置いた |
| `lint/unused-legend-entry` | warning | 凡例の項目と同じ見本の辺・node が図にない |

`layout/structured-only` の対象に、辺の `labelAt` / `labelSide`、`figure.layout.align` / `fanIn`、`legend` を加えました。部品の manifest の `engines` に対称な `layout/auto-only` も追加しましたが、組み込みの部品では使いません。

## 互換性

- Figure Schema は v1 のままで、追加はすべて任意フィールドと部品です。CLI のオプションは変わりません。
- 新しいフィールドを使わない auto（D2/ELK）の図の SVG / PDF / PPTX は、版に関する metadata（`sumi-version` など）を除いて変わりません。structured の図も、新しいフィールドと `legend` を使わなければ、版に関する metadata を除いて変わらないのが基本です。ただし、下記の辺の決め方の変更で経路が変わる図があります。同梱の作例・ギャラリー・fixture では、版の表記を除いてバイト単位で同じことを確かめています。
- **交差の info が新しく出ることがあります。** 交差のある既存の structured の図では、`sumi render` と `sumi lint --geometry` に `layout/edge-crossing`（info）が出ます。終了コードは変わりません。
- **anchor のない structured の図は、経路が変わることがあります。** 配置の木から辺を決める規則（上記）は既定で有効です。同梱の作例・fixture・#109 の 4 図では経路がバイト単位で同じですが、箱の向きと中心の差が食い違う配置では、出入りする辺が変わります。
  - 悪くなる場合もあります。#109 の図 3 から anchor を除いた版では、交差は 4 → 3 点に減る一方、excess（各辺の経路長と両端のマンハッタン距離の差の和）が 16.2 → 51.7mm、遠回りの辺が 1 → 3 本に増えました。同じ口に端が集まり、合流した線に乗るために回り込むためです。
  - このような図は、`fanIn: spread`（上の例で遠回り 0 本）を書くか、`fromAnchor` / `toAnchor` で辺を指定してください。
- 凡例の追加で、未知の部品・種類違いの診断の hint が示す部品の一覧に `legend` が加わります。`sumi catalog --json` の部品に `engines` が加わります（`legend` だけが持ちます）。
- 固定版 D2 は v0.9.0、同梱フォントは BIZ UD Gothic 1.051 と STIX Two 2.13、Tabler Icons は 3.49.0 のままです。
- 設計の詳細は、[設計 §6.27〜§6.34](https://github.com/nishide-dev/sumi-diagram/blob/v0.5.0/docs/design/phase1.md#627-127-のグループ見出しの位置groupslabelat) を参照してください。

## 既知の不具合

- structured の図で、同じ 2 要素を結ぶ平行な辺（例: `a → b` を 2 本）が、1 本の線に重なって描かれることがあります（[#143](https://github.com/nishide-dev/sumi-diagram/issues/143)）。v0.4.1 の入りと出の口の分離（#113）による既存の挙動で、v0.5.1 で直す予定です。それまでは、`fromAnchor` / `toAnchor` で 2 本を別の位置に指定してください（例: 1 本目は `fromAnchor: "east:0.3"`・`toAnchor: "west:0.3"`、2 本目は `"east:0.7"`・`"west:0.7"`）。
