# Sumi v0.20.1

v0.20 の Skill を実際の資料で使ってみた結果から作った版です。最近の会議の論文 4 本・tech report 3 本・技術資料 3 本の計 10 本から、新しいエージェントが v0.20.0 の Skill どおりに図を 1 枚ずつ作り、別のエージェントのレビューと利用者のフィードバックで足りないところを洗い出しました（[#639](https://github.com/nishide-dev/sumi-diagram/issues/639)、記録は [research/639-dogfood-v0.20](https://github.com/nishide-dev/sumi-diagram/tree/v0.20.1/research/639-dogfood-v0.20)）。幅・高さを手で合わせずに済むヒント、横に並んだパネルの揃え、線の出どころとラベルの持ち主、凡例の置き場所と色の説明、matrix とシーケンス図の表現、`sumi` テーマの減光の色を改めています。実装は milestone「[v0.20.1](https://github.com/nishide-dev/sumi-diagram/milestone/41)」です。

## 幅・高さのヒント

- **実際に効く手段を試す幅のヒント**（[#640](https://github.com/nishide-dev/sumi-diagram/issues/640)）: `geometry/exceeds-page-width` などの幅のヒントが、凡例（`flow: row`）の `perRow`、matrix の `flush: true`（と `labelAt: above`）・`cellWidth`、`place` の x 座標（外側を内へ・列の間を詰める・中央へ寄せる）も試します。どれも写しを配置・配線・lint して、収まり error / warning が増えないものだけを示します。1 つでは足りない修正（`Narrower but not enough alone`）には、道筋の値を 1 つ足した組み合わせも試します。
- **値の下限**（#640）: gap と `participantGap` は 2mm、padding は 4pt までを先に試し、それより小さい値は何も収まらないときだけ `(last resort …)` として出します。`Verified layout edits` の gap と `attach.gap` も 0mm ではなく 2mm を示します（もとが 2mm 以下のときを除く）。
- **自動で増えた padding の理由**（#640）: 矢じりの扇形・U ターンなどで padding が自動で増えたとき、`--explain-width` とヒントの `Width path` がその量と理由を言います（`--json` の `widthTree` に `padding.grown`）。増えた padding は幅の候補から外します。
- **シーケンス図の高さのヒント**（#640）: `geometry/exceeds-page-height` などで、`rowGap`（確かめた値）・`iconAt: top` の参加者・帯・1 行のラベル・図の分割を勧めます。凡例が幅を決めているという注記は、幅の道筋が本当にその凡例で終わるときだけ出します。

## 横に並んだパネル

- **`row.panels: true`**（[#641](https://github.com/nishide-dev/sumi-diagram/issues/641)）: row に直接並べたグループ（パネル）が row の高さを取り、中身を見出しの直下に置き、見出しの帯を揃えます（揃えると row が高くなるときは揃えません）。中のノードは row の `align` のままで、図は大きくなりません。Skill のベースレイアウト `three-panel-flow` はこの書き方にしました。
- **揃っていないパネルの lint `geometry/panel-misaligned`**（#641、info）: `panels` のない row で、パネルの枠の上端・下端・見出し・キャプションが 1mm 以上ずれていれば、row ごとに知らせ、`panels: true` を足す場所を示します。`geometry/content-band` と `geometry/group-empty-area` のヒントには `contentAlign: top` を書く具体的な位置を出します。
- **見出しを枠の上に置いたグループで stretch の row が伸びる不具合**（[#663](https://github.com/nishide-dev/sumi-diagram/issues/663)）: `align: stretch` の row / stack に `labelAt: above-*` のグループがあると、見出しを 2 回数えて枠と図がその分高くなっていました。伸ばすグループは見出しを 1 回だけ数えます。

## `figure.layout.align` の副作用

- **`layout/align-widened-gap`**（[#646](https://github.com/nishide-dev/sumi-diagram/issues/646)、info）: 揃えのために stack / row の 1 つの gap だけが大きく広がったとき（キャプションがパネルから離れたときを含む）、2 つの項目・前後の幅・原因の制約を示します。`alignGrowth: allow` で消えます。
- **`layout/align-uneven-stretch`**（#646、info）: `align: stretch` で同じ大きさにした枠が、揃えたあとに 0.5mm を超えて食い違うと知らせます。
- **制約の `move: <id> | [ids]`**（#646）: 揃えるときに動かしてよい項目を選べます（注記ではなくセルが動く、などを避ける）。制約の項目でない ID は `layout/invalid-align-move`（error）です。新しい info と `align-splits-tokens`・`align-grew-figure` のヒントが `move` の案を示します。

## 線の出どころとラベル

- **`fromAnchor` / `toAnchor` の `block` と `block:<side>`**（[#642](https://github.com/nishide-dev/sumi-diagram/issues/642)）: tokens 全体・matrix・グループから出る（入る）線を、要素全体の辺の中央に付け、ほかの線と分け合いません。枠を描かない要素（tokens・matrix・`plain` のグループ）では、セル全体にかかる括弧を描いて線をその中央から出します。括弧は配線のあとに足すので、配置は変わりません。ノードやセルに書くと `layout/block-anchor`（error）です。
- **紛らわしいラベルの lint `geometry/edge-label-ambiguous`**（#642、warning）: ラベルが自分の線とほぼ同じ近さで別の線のそばにあり、どちらの線のものか読めないときに知らせ、反対側の `labelSide`・`labelStyle: tag`・`labelAt` を勧めます。`geometry/edge-label-detached` のヒントは、確かめた編集がなければ `labelStyle: tag` を先に挙げ、最も長い直線の区間と、ラベルを置くのに要る長さを示します。
- **辺の札 `labelStyle: badge`**（[#649](https://github.com/nishide-dev/sumi-diagram/issues/649)）: `tag` と同じ置き方で、丸い枠（1〜2 文字は円、長いラベルは pill）に入れます。手順の番号向けです。
- **バスにしない lane `lane.bus: false`**（#649）: 同じ側の lane を 1 本の幹にまとめず、それぞれ自分の `offset` を通します。

## ルーター

- **向かいの辺へ Z で入る**（[#657](https://github.com/nishide-dev/sumi-diagram/issues/657)）: 片方の端にだけアンカーを書いた線で、もう一方の端がその辺の先にあるのに、既定の辺へ 3 回曲がって横から入っていたとき、ルーターはアンカーに向かう辺へ 2 回曲がり（Z）で入る経路を試し、ほかの線の曲がりやエラーを増やさなければ採ります（1 図 4 回まで）。書いたアンカーは変えません。ルーターが残した場合は `geometry/avoidable-bend` が報告し、確かめた `toAnchor` を示します。

## 凡例と色

- **凡例を空いた所に浮かせる `props.float`**（[#643](https://github.com/nishide-dev/sumi-diagram/issues/643)）: `top-left`・`bottom` などの角・辺、または `{at, inset}` で、凡例を容器（図全体か `group:` のグループ）の中身の上に重ねて置き、図の幅・高さを増やしません。シーケンス図では、凡例にかかる空いた lifeline が凡例の上で止まります。ルーターは浮かせた凡例を避けず、辺の経路は凡例がないときと同じです。
- **浮かせた凡例の lint**（#643）: 凡例がノード・グループの枠や見出し・辺・ラベルに重なる、または集合の輪郭を横切ると `geometry/float-overlap`（warning）、容器より大きいと `layout/float-too-large`（warning）、配置の木にも書くと `layout/duplicate-placement` です。
- **説明のない色 `lint/unexplained-colors`**（#643、info）: 種類を表すように使った有彩色が 3 つ以上あり、凡例も色の名前を含むラベルもないときに知らせます。Skill にも「色に意味を持たせたら凡例か本文で説明を残す」を書きました（[#648](https://github.com/nishide-dev/sumi-diagram/issues/648)）。
- **`sumi` / `sumi-dark` の減光を `muted` と分けた**（[#636](https://github.com/nishide-dev/sumi-diagram/issues/636)）: 減光（`dim: true`）の色を `sumi` は #4e566b → #8a8f9d、`sumi-dark` は #acbac4 → #7a8595（どちらもキャンバスに対して 3.2:1）にし、本文 > `muted` > 減光の順に淡くなるようにしました。あわせて、すでに減光の色より淡いノードの線は減光で濃くしない規則にしました（全テーマ）。

## matrix

- **色の段階 `props.scale`**（[#644](https://github.com/nishide-dev/sumi-diagram/issues/644)）: セルを `{value: 78.5}` と書くと、tone の淡い端から濃い端までの色で塗ります（`steps` で区間ごと、`from > to` で逆向き、`showValues` で値の表示）。文字は 4.5:1 を保ちます。凡例の `{scale: <matrix>}` で段階の帯を描き、scale のない matrix を指すと `ref/unknown-scale`（error）です。
- **結合セル `span`** と **列の見出しの回転 `headerRotate: 90 | -90`**（#644）: `span: 2` / `span: {rows, columns}` で HTML の表と同じようにセルを結合し、列の見出しを縦に回して細い列にします。
- **`rules: true` の matrix の凡例の見本**（#644）: セルにない枠を見本から外しました。
- 新しい作例 [`examples/transfer-heatmap`](https://github.com/nishide-dev/sumi-diagram/blob/v0.20.1/examples/transfer-heatmap/transfer-heatmap.sumi.yaml)（架空の値）で、段階・回転した見出し・`rules: true`・`span` を使っています。

## シーケンス図

- **フラグメントの枠はテーマのグループの枠**（[#645](https://github.com/nishide-dev/sumi-diagram/issues/645)）: `variant` も `tone` も書かないフラグメントを、塗りなしで、テーマのグループの枠の色と幅（`sumi` は 0.5pt の淡い灰色）で描きます。`themeOverrides.groupStroke` / `frameWidth` も効き、`variant: outlined` で従来の濃い 1pt の線になります。枠の左右の辺と lifeline の間も広げました。
- **参加者の高さを揃える**（#645）: 縦に伸ばせる参加者は最も高い参加者と同じ高さになり、上端と下端が揃います。
- **複数の宛先 `to: [b, c]`**（#645）: sequence の行のメッセージは宛先をリストで書け、宛先ごとに 1 本の矢印を続く行に描きます（ラベルは最初の 1 本だけ）。sequence の外で使うと `layout/multiple-targets`（error）です。

## 小さな表現

- **流れから外す注記 `attach.inFlow: false`**（#649）: 付けたノードが属するグループ（tokens の枠など）の大きさを変えず、行の中のセルが中心からずれません。
- **入れ子の place の原点 `origin: place`**（#649）: `at` を「グループ自身の place の [0, 0] が来る点」にし、入れ子の座標をページの座標として書けます。誤用は `layout/invalid-place-origin`（error）です。

## lint のヒントの精度

- **`geometry/token-column-drift` のヒント**（[#647](https://github.com/nishide-dev/sumi-diagram/issues/647)）: 決まり文句をやめ、2 行のセルの幅・gap・始まりの差を測って示します。手前のノードの幅が原因なら、同じ幅で配置し直して列が揃ったときだけ `Verified:` として名指しします。
- **`geometry/edge-near-edge`**（#647）: 1 つの点に集まる斜めの線（扇形）を報告しなくなりました。

## Skill

- **`sumi` を勧めるテーマに**（#648）: SKILL.md の手順・Essentials の例・論文の図とスライドのレシピを `sumi`（スライドは `sumi` + `textScale: 2`）を基本に書き直し、`paper` はパステルの ML 論文の調子を頼まれたときに限りました。`docs/themes.md` と `docs/usage.md` の表にも `sumi` / `sumi-dark` を加えました。
- **下絵を省いてよい場合**（#648）: `sequence-diagram` と `state-machine` のベースレイアウトがそのまま当てはまるときは下絵を省けます。info を意図どおりとして残す前に、ヒントの直しを 1 度試すことも書きました。
- **スキーマエラーのヒント**（#648）: `iconSize: 1.2em` には数値（`iconSize: 1.2`）を、`grid` の `gap` には `rowGap` / `columnGap` を示します。

## 互換性

- Figure Schema に次が加わりました（書かなければ従来どおりです）: `row.panels`、`figure.layout.align` の制約の `move`、`fromAnchor` / `toAnchor` の `block`・`block:<side>`、`labelStyle: badge`、`lane.bus`、`attach.inFlow`、place の `origin: place`、`legend` の `props.float` と `{scale}` の entry、`matrix` の `scale`・`span`・`headerRotate`、sequence の行の `to` のリスト。
- **出力が変わる変更**:
  - **シーケンス図のフラグメントの枠**（#645）: `variant` も `tone` も書かないフラグメントは、すべてのテーマでそのテーマのグループの枠（塗りなし）で描きます。`sumi` / `sumi-dark` は淡い 0.5pt、`paper` は淡い枠、`minimal`・`color`・`academic`・`slides` は同じ幅で少し明るい灰色になり、`llama` ではこれまで見えなかった枠が細線で見えるようになります。枠の左右の辺と lifeline の間が広がり（screen-doc で 5.5pt → 9pt）、枠のある図は少し広くなります。高さの違う参加者は最も高い参加者に揃います。Skill のベースレイアウト `sequence-diagram` を再生成しました。
  - **`sumi` / `sumi-dark` の減光の色と、減光でのノードの線**（#636）: 減光した要素は一段淡くなります。すでに減光の色より淡いノードの線は濃くしません（全テーマ。`llama` の operator の枠はそのまま）。`muted` の flow arrow（`block-arrow`・`triangle-arrow`・`chevron`）は減光で濃い灰色にならず淡い塗りのまま、黄色の `solid` の減光に付いていた灰色の枠もなくなります。ギャラリーの `dim.sumi`・`dim.sumi-dark`・`dim.llama` が変わりました。
  - **向かいの辺への Z**（#657）: 片方にだけアンカーを書き、既定の辺へ 3 回曲がって入っていた線は、Z で向かいの辺に入るようになることがあります。コミット済みの作例・ギャラリーでは変化はありませんでした。
  - **見出しを枠の上に置いたグループのある stretch の row / stack**（#663）: 見出しの分だけ高くなっていた枠と図が、本来の高さになります。親から `stretch` を継承した箱は従来どおりです。
  - **`rules: true` の matrix の class を載せた凡例**（#644）: 見本の枠がなくなります（リポジトリ内には該当する図なし）。
- **新しい lint**: warning の `geometry/edge-label-ambiguous`・`geometry/float-overlap`・`layout/float-too-large`、info の `geometry/panel-misaligned`・`layout/align-widened-gap`・`layout/align-uneven-stretch`・`lint/unexplained-colors` が加わり、既存の図に新しく出ることがあります。error の `layout/block-anchor`・`layout/invalid-align-move`・`layout/invalid-place-origin`・`layout/multiple-targets`・`ref/unknown-scale` は新しい書き方の誤用だけで出ます。作例 `gcn` には `geometry/panel-misaligned` 2 件と `layout/align-widened-gap` 1 件の info が増えます（図は変わりません）。
- 幅・高さのヒントと `geometry/token-column-drift` のヒントの文が変わりました（#640、#647）。`--json` の `widthTree` には `padding.grown` が加わります。
- **内部 API**（[#664](https://github.com/nishide-dev/sumi-diagram/issues/664)）: lint の規則の一覧の定数 `BUILTIN_GEOMETRY_RULES`・`ALL_LINT_RULES` は、初めて使うときに作る関数 `builtinGeometryRules()`・`allLintRules()` になりました。lint のモジュールを最初に import すると初期化前のアクセスで落ちる不具合の修正で、出力は変わりません。
- 論文の再現図（作例）の出力は変わりません（版の表記を除く。既存の再現図のハッシュは更新しておらず、新しい作例 `transfer-heatmap` の行を加えただけです）。
- 固定版 D2 は v0.9.0、同梱フォント・Tabler Icons・Fluent Emoji Flat・Takumi は v0.20.0 と同じです。
- 設計の判断は、[docs/design/decisions](https://github.com/nishide-dev/sumi-diagram/tree/v0.20.1/docs/design/decisions) の `636-sumi-dim-colors.md`、`640-fit-hints.md`、`641-panel-rows.md`、`642-block-anchor.md`、`643-floating-legends.md`、`644-matrix-scale-span.md`、`645-sequence-fragments.md`、`646-align-side-effects.md`、`647-lint-hint-causes.md`、`649-small-expression-gaps.md`、`657-facing-z.md`、`663-above-title-stretch.md`、`664-lazy-rule-list.md` を参照してください。
- **既知の制限**:
  - `sumi` / `sumi-dark` の凡例の枠は、パネル（#634）のような淡い細線ではなく従来の濃い枠のままです。
  - `block` の括弧は配線のあとに足すので、ルーターの診断（`layout/edge-crossing`、ラベルの重なり、見出しをまたぐ線）は括弧を見ません（geometry lint は括弧を線の一部として測ります）。
  - 浮かせた凡例は空いた場所を自動では探さず、辺も凡例を避けて回りません（重なりは `geometry/float-overlap` が知らせます）。集合の規則と幅のヒントは浮かせた凡例を見ません。
  - 向かいの辺への Z は 1 図 4 本まで試し、対象の図では配線し直す分だけ時間がかかります。
  - `row.panels` は tilted plane・tokens・matrix・legend をパネルとして扱いません。`#663` の修正は、`align` を書かずに親から `stretch` を継承した箱には効きません。
  - `align` の `move` の案はヒントに出ますが、試しの配置では確かめていません。
