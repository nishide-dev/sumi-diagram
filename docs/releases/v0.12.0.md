# Sumi v0.12.0

エージェントが Sumi と Skill だけで論文の図を作るときの詰まりを減らすリリースです。ViT の Figure 1 を題材にした評価で見つかった問題を直し、パネルの区切り線、画像資産の再利用と切り出し、幅の超過の内訳を加えました。Skill には論文図のデザイン原則と、YAML を書く前にレイアウトを計画する手順を加えています。計画は [#236](https://github.com/nishide-dev/sumi-diagram/issues/236)、実装は milestone「[v0.12.0 — Agent authoring](https://github.com/nishide-dev/sumi-diagram/milestone/23)」です。

## 新しい部品と書き方

- **`separator`**（[#309](https://github.com/nishide-dev/sumi-diagram/issues/309)）: パネルを区切る線。structured の図だけで使えます。row の直接の項目なら縦線、stack なら横線になり、その箱の幅（または高さ）全体に伸びます。`default` と `dashed` は破線、`solid` は実線です。線の両側の余白は arrange の `gap` で決めます。矢印の端点や grid の直接の項目には使えず、そのときは位置付きの error になります（`component/separator-connection`、`component/separator-placement`）。
- **`figure.assets`**（[#310](https://github.com/nishide-dev/sumi-diagram/issues/310)）: 図の中で何度も使う SVG や画像を 1 か所に定義し、`image` の `props.asset: <ID>` で参照します。
  - **`props.crop: [x, y, 幅, 高さ]`**: 資産の SVG の viewBox 座標で、一部だけを切り出します。1 枚の絵からパッチを切り出すときに使います。
  - **`tokens` の画像セル**: `{ asset: <ID>, crop: [...] }` のセルで、トークン列に画像を並べられます。
  - 資産は図ごとに 1 回だけ検査し、問題は `figure.assets.<ID>` の中の行・列を指します。
- **`operator` の `props.size: regular | large | xlarge`**（[#311](https://github.com/nishide-dev/sumi-diagram/issues/311)）: ⊕ などの円と記号を、Theme の大きさの 1 / 1.5 / 2 倍にします。

## 配置の改善

- **複数行の `tokens`**（[#305](https://github.com/nishide-dev/sumi-diagram/issues/305)）: `lines` のセルを `figure.layout.align` に指定したとき、行の内側に空白を入れて列の対応を崩すことがなくなりました。複数行の塊は 1 つのまま動き、動かせないときは位置付きの `layout/unsatisfied-align` を出します。
- **grid の `span` と、セルごとの `align`**（[#306](https://github.com/nishide-dev/sumi-diagram/issues/306)）: 制約を満たせないとき、原因ごとに分けた hint を出します。修正案は、実際に配置を試して効果を確かめたものだけを出します。

## 新しい診断

- **幅の超過の内訳**（[#307](https://github.com/nishide-dev/sumi-diagram/issues/307)）: `geometry/exceeds-page-width` が、図の幅を決めている要素と間隔を mm で示します。修正案は、配置を試して何 mm 縮むかを測り、効く順に並べます。
- **`sumi fmt` の結果**（[#312](https://github.com/nishide-dev/sumi-diagram/issues/312)）: ファイルごとに `changed` / `unchanged` を stderr に 1 行出します。stdout・`--check`・`--stdout` は変わりません。
- `sumi catalog --json` の props の `enum` と `default` の読み方を、help と文書に書きました。

## Skill

- **参照文書を整理しました**（[#308](https://github.com/nishide-dev/sumi-diagram/issues/308)）。古い記述を直し、`references/html.md` を分け、全体を約 207KB から約 171KB に減らしました。
- **論文図のデザイン原則とレイアウト計画**（[#323](https://github.com/nishide-dev/sumi-diagram/issues/323)）:
  - 読む向き、目立たせる要素、整列、近さによるまとまり、空白、紙面の幅、色の役割、注記の置き場所の原則を、Sumi の書き方と結びつけて書きました。
  - YAML を書く前に、要素の役割を洗い出し、配置の候補を 2 案ほど略図で比べてから書き始める手順を加えました。空白は要素を足して埋めず、配置を変えて詰めます。
  - 論文図の手順を、「内容だけから設計する」場合と「参考の図がある」場合の 2 つに分けました。
  - 特定の論文の図をなぞった例は、中立な題材に差し替えました。
- **公開論文の完成例**（[#325](https://github.com/nishide-dev/sumi-diagram/issues/325)）: Transformer、DiT、CLIP、EmbeddingGemma 2 の YAML・アセット・PNG を `skills/sumi/examples/` に同梱しました。ユーザーがそのモデルや図のスタイルを指定したときだけ参照するものです。リポジトリの `examples/<name>/<name>.sumi.yaml` は、Skill 側の実体へのリンクになりました。

## 互換性

- Figure Schema は任意の追加だけです。CLI のコマンドは変わりません。
- **`paper` テーマの framed の `image` と `html` は、枠の線が 1pt から 0.5pt になりました**（#311）。矢印の線の太さにそろえるためです。ほかの Theme の framed の枠は変わりません。
- それ以外の図の SVG / PDF / PPTX / D2 は、v0.11.0 と同じです（版に関する metadata を除く）。
- 固定版 D2 は v0.9.0、同梱フォント・Tabler Icons・Fluent Emoji Flat・Takumi は v0.11.0 と同じです。
- CI のテストを OS ごとに 4 つに分けて並列に実行するようにしました（[#320](https://github.com/nishide-dev/sumi-diagram/issues/320)）。配布物には影響しません。
- 設計の詳細は、[設計 §6.86〜§6.94](https://github.com/nishide-dev/sumi-diagram/blob/v0.12.0/docs/design/phase1.md#686-305-の複数行-tokens-のセルを基準にした整列)を参照してください。

## インストールと更新

```sh
curl -fsSL https://raw.githubusercontent.com/nishide-dev/sumi-diagram/main/install.sh | sh
```

版を固定するときは `SUMI_VERSION=0.12.0` を付けます（README の[インストール](https://github.com/nishide-dev/sumi-diagram/blob/v0.12.0/README.md#install)）。Skill は `npx skills add nishide-dev/sumi-diagram --skill sumi` で更新します。

公開準備は [#327](https://github.com/nishide-dev/sumi-diagram/issues/327) です。今後の計画は [#236](https://github.com/nishide-dev/sumi-diagram/issues/236) で管理します。
