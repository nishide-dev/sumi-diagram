# Sumi v0.15.0

グラフ（頂点と辺）を含む論文の図を描くためのリリースです。頂点を座標で置く箱、重ねたカードとして描くグループ、一点に集まって再び広がる曲線、図ごとの配色の上書きを加え、GCN（Kipf & Welling 2017）の図 1 を再現した例を追加しました。あわせて、v0.14.0 の確認で残った診断と Skill の問題を直しました。計画は [#236](https://github.com/nishide-dev/sumi-diagram/issues/236)、実装は milestone「[v0.15.0 — Graph figures](https://github.com/nishide-dev/sumi-diagram/milestone/26)」です。

## 新しい書き方

- **座標で置く箱 `place`**（[#364](https://github.com/nishide-dev/sumi-diagram/issues/364)）: structured の arrange に `place: { unit: 5mm, items: [{ item: x1, at: [2.4, 0] }, …] }` と書くと、各項目の中心を単位長さの倍数（小数・負の値も可、y は下向き）の位置に置きます。
  - 中の項目は普通のノードやグループのままで、ラベル・tone・attach・辺がそのまま使えます。同じ座標と単位を 2 つのグループに書けば、同じ形のグラフになります。
  - 箱の大きさは項目の外形の和で、親の中では他の箱と同じように並びます。
  - 項目の外形の重なりは warning `layout/place-overlap`（両方の位置つき）です。接するのは許します。
- **重ねたカードとして描くグループ**（[#365](https://github.com/nishide-dev/sumi-diagram/issues/365)）: グループに `props.layers: { count: 4, offset: 2pt }` を書くと、枠を右上にずらした複数枚のカードとして描きます（チャンネル数や特徴マップの数を表す図）。画像の `layers` と同じ書き方です。
  - 前のカードがタイトル・中身・余白を持ち、配置・障害物・lint・キャプションは重なり全体の外形で扱います。
  - 後ろのカードは飾りです。辺は後ろのカードの帯を横切ってよく、グループの境界は前のカードの枠です。辺のラベルは前後の枠を避け、避けられないときは `geometry/label-collision` を出します。
  - `plain` は `component/invalid-prop`、auto の図は `layout/structured-only` です。
- **曲線 `route: curve`**（[#366](https://github.com/nishide-dev/sumi-diagram/issues/366)）: structured の edge に指定すると、端点どうしを 1 本の 3 次ベジェ曲線で結びます。
  - hidden junction に集まる曲線と、そこから出る線は、同じ向きの接線を共有するので、複数の線が一点に集まって再び広がる束がなめらかにつながります。
  - 端点・アンカーは `route: straight` と同じ規則です。矢じりは端の接線に沿い、`tone` で色を変えられます。障害物は避けず、ノードやラベルとの重なりは lint が位置つきで知らせます。
  - SVG・PDF・picture PPTX・editable の freeform PPTX で曲線を保ちます。editable の glued PPTX は `pptx/unsupported-geometry` です。
- **配色の上書き**（[#380](https://github.com/nishide-dev/sumi-diagram/issues/380)）: `figure.themeOverrides` に次を加えました。どれも `#RRGGBB` です。
  - `tones: { <tone>: { fill?, line?, text? } }`: その tone を使うすべての場所（淡い塗り、tinted・outlined の枠と文字、tone つきの辺と矢じりと辺のラベル、行列のクラス、凡例、`\textcolor`、HTML の `--sumi-accent`）に一貫して効きます。`solidFills` を同じ tone に書いたときは `solidFills` が優先です。
  - `groupFill` / `groupStroke`: グループ（重ねたカードを含む）の塗りと枠の色。破線のグループは `dashedGroupStroke` が優先です。
  - 上書きした文字の色が、その tone の塗り、または白地（outlined の文字、辺のラベル、`\textcolor`）に対して 4.5:1 に届かないときは warning `theme/low-contrast` を出します。図で実際に使う tone と場所だけを確かめます。

## 例

- **GCN**（[#367](https://github.com/nishide-dev/sumi-diagram/issues/367)、[`examples/gcn/`](https://github.com/nishide-dev/sumi-diagram/tree/v0.15.0/examples/gcn)）: Kipf & Welling (2017), *Semi-Supervised Classification with Graph Convolutional Networks*, Figure 1 の再現です。上の 4 つの機能をまとめて使い、全幅（178.86mm × 65.44mm）に縮小なしで収まります。(b) の t-SNE 風の散布図は、決定的なスクリプト（`assets/generate.ts`）で作った合成データで、論文の画像やデータは使っていません。

## 診断の改善

- **直線が隣をかすめる**（[#369](https://github.com/nishide-dev/sumi-diagram/issues/369)）: `route: straight` の辺が、端点以外のノードや `tokens` のセルの輪郭に線の太さの分まで近づくと、`geometry/edge-through-node`（warning）で「touches the outline」と知らせます。以前は 0.5pt を超えて入り込んだときだけでした。
- **attach したラベルが接する**（[#371](https://github.com/nishide-dev/sumi-diagram/issues/371)）: 角などに attach したラベルが、他の文字と重ならずに接している（1pt 未満の間隔）ときも `geometry/label-collision` を出します。
- **幅の超過の hint を短く**（[#368](https://github.com/nishide-dev/sumi-diagram/issues/368)）: `geometry/exceeds-page-width` の hint は、超過量・幅を決めている行・確かめた修正案を先に書き、細かい内訳は `related` に移しました（`--json` と、テキスト出力の `related:` 行に残ります）。修正案の内容と順位は変わりません。
- **`sumi catalog --section targets`**（[#363](https://github.com/nishide-dev/sumi-diagram/issues/363)）: `minFontSize` を書くと数式の添字も確かめることを説明に反映しました。

## Skill

- **`scripts/preview`**（[#370](https://github.com/nishide-dev/sumi-diagram/issues/370)）: macOS の Quick Look の正方形のサムネイルを、図の縦横比で切り出すようにしました。横長の図がほとんど白い画像になっていた問題を直しました。
- `structured.md` と `figure-format.md` に、`place`、グループの `layers`、`route: curve`、配色の上書きを加えました。

## 互換性

- Figure Schema は任意の追加だけです。CLI のコマンドは変わりません。
- 既存の図の SVG / PDF / PPTX / D2 は、v0.14.0 と同じです（版に関する metadata を除く）。
- 診断の変化:
  - `route: straight` の辺が他のノードやセルをかすめる図、attach したラベルが他の文字に接している図で、新しく warning が出ることがあります（上記）。
  - `geometry/exceeds-page-width` の hint の文言と構成が変わりました（細かい内訳は `related`）。
- 固定版 D2 は v0.9.0、同梱フォント・Tabler Icons・Fluent Emoji Flat・Takumi は v0.14.0 と同じです。
- 設計の判断は [docs/design/decisions](https://github.com/nishide-dev/sumi-diagram/tree/v0.15.0/docs/design/decisions) の各ファイル（#364〜#366、#369、#371、#380）を参照してください。

## インストールと更新

```sh
curl -fsSL https://raw.githubusercontent.com/nishide-dev/sumi-diagram/main/install.sh | sh
```

版を固定するときは `SUMI_VERSION=0.15.0` を付けます（README の[インストール](https://github.com/nishide-dev/sumi-diagram/blob/v0.15.0/README.md#install)）。Skill は `npx skills add nishide-dev/sumi-diagram --skill sumi` で更新します。

公開準備は [#383](https://github.com/nishide-dev/sumi-diagram/issues/383) です。今後の計画は [#236](https://github.com/nishide-dev/sumi-diagram/issues/236) で管理します。
