# Sumi v0.20.0

v0.19 の Skill を実際の資料で使ってみた結果から作った版です。最近の会議の論文・tech report・技術資料の 10 本から、新しいエージェントが v0.19.1 の Skill どおりに図を 1 枚ずつ作り、別のエージェントのレビューと線の経路の集計、利用者のフィードバックで足りないところを洗い出しました（[#603](https://github.com/nishide-dev/sumi-diagram/issues/603)、記録は [research/603-dogfood-v0.19](https://github.com/nishide-dev/sumi-diagram/tree/v0.20.0/research/603-dogfood-v0.19)）。無駄な曲がりのない線、描き直さずに幅を合わせること、アイコンとシーケンス図、辺のラベルの置き場所、`sumi` テーマのパネルの見た目を改めています。実装は milestone「[v0.20.0](https://github.com/nishide-dev/sumi-diagram/milestone/40)」です。

## 線を真っ直ぐに

- **`figure.layout.straighten` を既定に**（[#618](https://github.com/nishide-dev/sumi-diagram/issues/618)、[#620](https://github.com/nishide-dev/sumi-diagram/issues/620)）: 構造化レイアウトで、向かい合う端が少しずれた線を、線を曲げる代わりにノード・グループ・入れ子の箱を所属する箱の空きの範囲でずらして一直線にします（人が図を描くときと同じ「出る側か入る側を動かす」）。ほかの線の曲がりが増える・図が大きくなる・重なる移動は採りません。動かしきれないときは、アンカーのない端を辺に沿って相手の線へ寄せます（枠のない `plain` のグループの端は寄せません）。省略すると有効で、`straighten: false` を書けば v0.19 までの配置とバイト単位で同じになります。auto 配置は対象外です。
- **避けられる曲がりの lint `geometry/avoidable-bend`**（[#604](https://github.com/nishide-dev/sumi-diagram/issues/604)、warning）: 書いたアンカーが原因の S 字・迂回、注記ラベルや見出しが塞ぐ階段、曲がりの間の 2mm 未満の小さな段、ジャンクションの直前で幹を外す折れを名指しします。アンカーの値のヒントは、図の写しに書いて本物のルーターで配線し直し、約束した曲がり数になり、ほかの線が悪くならないと確かめたものだけを出します。経路そのものは変えません。
- **ノードの移動を勧める `geometry/relocatable-node`**（[#621](https://github.com/nishide-dev/sumi-diagram/issues/621)、info）: grid の近くの空きセルや stack / row の別の位置へ端のノードを動かすと曲がりが減るとき、配置・配線・lint をやり直して確かめた移動を、`items` の具体的な書き換えとして示します。自動では動かしません。
- **線の通り道を指定する `edges[].lane`**（[#609](https://github.com/nishide-dev/sumi-diagram/issues/609)）: `lane: {side, offset, outside}` で、ループ・skip・戻り線の長い区間を指定した側・距離（またはグループの枠の外）に通します。同じ側の lane で源か先を共有する線は 1 本の幹（バス）にまとまります。描けないときは `layout/lane-blocked`（warning）で理由を言い、通常の配線にします。構造化レイアウトのみです。

## 幅を合わせる・下絵を合わせる

- **幅を決めている項目と、収まる値のヒント**（[#607](https://github.com/nishide-dev/sumi-diagram/issues/607)）: `geometry/exceeds-page-width` と `geometry/heavy-scaling` のヒントに、ページから幅を決める項目までの道筋（`Width path`、`Widest contributor`）を出します。`align: stretch` で皆が同じ幅に見えても、本当に幅を決めている凡例などを名指しします。収まる gap・`props.padding`・幅の値（`Fits <max>`）は、写しを配置・配線・lint して、収まって error / warning が増えないものだけを示します。
- **`sumi render --explain-width`**（#607）: 自然な幅の木全体を stderr に出します（`--json` では `widthTree`）。描画結果は変わりません。
- **`sumi catalog --sizes`**（[#611](https://github.com/nishide-dev/sumi-diagram/issues/611)）: 部品の既定寸法・余白・間隔・文字の大きさ・線の太さを、プロファイル・テーマ・密度・`--text-scale` ごとに出します。`--label` で実際のラベルでの自然な幅を、`--json` / `--css` で機械が読む形を出します。値は Skill の [`references/sizes.md`](https://github.com/nishide-dev/sumi-diagram/blob/v0.20.0/skills/sumi/references/sizes.md)（#607）と同じ生成コードから作るので、ずれません。
- **Skill の下絵テンプレート**（#611）: [`mockup-template.html`](https://github.com/nishide-dev/sumi-diagram/blob/v0.20.0/skills/sumi/references/mockup-template.html) の寸法を `sumi catalog --sizes --css` の出力そのものにし、幅を省いた箱は Sumi と同じ自然な大きさに、ラベルが入りきらない箱には赤い破線を付けます。

## パネルの中身と見出し

- **`groups[].contentAlign: top | center | bottom`**（[#613](https://github.com/nishide-dev/sumi-diagram/issues/613)）: `align: stretch` などで中身より高くなったパネルで、中身を上端（下端）に置き、見出しの下と中身の下に空き帯ができないようにします。既定の `center` は従来どおりです。
- **`groups[].matchLabelHeight: <name>`**（#613）: 同じ名前のグループが最も高い見出しの帯を取り、1 行と 2 行の見出しが混ざっても兄弟パネルの最初の行が揃います。
- **空き帯の lint `geometry/content-band`**（#613、info）: 伸ばされたグループの中身の上下に 4mm 以上の空きがあれば知らせ、確かめた `contentAlign: top` を示します。

## 辺のラベル

- **ラベルの既定の側**（[#610](https://github.com/nishide-dev/sumi-diagram/issues/610)）: `route: straight` / `curve` の線で `labelSide` を書かないラベルは、向きによらず線の上（垂直から 5° 以内は右）に置きます。これまでは「進行方向の左」で、左向きの線では線の下になっていました。直交のルーターの既定（横の線分の上、縦の線分の右）とそろいます。
- **`labelAt` に割合**（#610）: `labelAt: 0.3` のように 0〜1 の数で、経路の長さ（直線・曲線では弧長）に対する位置を指定できます。
- **`labelStyle: tag`**（#610）: 文字を線の上の小さな札（下の色で塗り、線の色の細い枠）に入れます。構造化レイアウトのみです。
- **ラベルの lint**（#610）: `geometry/edge-label-detached`（info、ルーターが置いたラベルが線から離れた）と `geometry/edge-label-touches-line`（warning、文字が線に触れる・横切る）。ヒントは `labelAt` と `labelStyle: tag` を配線し直して確かめたものです。

## 部品

- **アイコンとラベルを 1 つのノードに**（[#605](https://github.com/nishide-dev/sumi-diagram/issues/605)）: `icon` と `label` の両方を持つノードで、`iconAt: left | top` でアイコンを文字の左（既定）か上に描きます。ノードは両方が入る大きさになり、`iconSize`・`sublabel` も効きます。構造化レイアウトのみです（auto では従来どおり `asset/icon-with-label`）。
- **アイコンの使い方**（[#606](https://github.com/nishide-dev/sumi-diagram/issues/606)）: Skill の [`references/assets.md`](https://github.com/nishide-dev/sumi-diagram/blob/v0.20.0/skills/sumi/references/assets.md) に使う場面・使わない場面、1 つの図で 1 つのファミリー、概念と Tabler の名前の対応表を書きました。行き過ぎは info の `geometry/icon-family-mix`（Tabler と絵文字の混在）と `geometry/icon-overuse` で知らせます。ベースレイアウト `actors-and-tools` を加えました。
- **シーケンス図 `arrange: {sequence: …}`**（[#630](https://github.com/nishide-dev/sumi-diagram/issues/630)）: `participants` と `rows`（メッセージ・自分自身へのメッセージ・注記・同じ行に並べる帯・`fragment` の枠）を書くだけで、y 座標や lifeline の線を書かずに描けます。lifeline の間隔はラベル・注記・枠から決まり、ルーター・SVG / 編集可能 PPTX・lint はそのまま使えます。ベースレイアウト `sequence-diagram` を加えました。
- **`matrix` の見出しと表のスタイル**（[#612](https://github.com/nishide-dev/sumi-diagram/issues/612)）: `wrapHeaders` / `columnHeaderWidth` で見出しを語の境目で折り返し、`labelAt: above*` でタイトルを枠の外に出し、`rules: true` で罫線だけの表にします。`muted` のセルと凡例の見本は淡い灰色で描きます。
- **線の点線と束**（[#614](https://github.com/nishide-dev/sumi-diagram/issues/614)）: `edges[].dash: dashed | dotted` で variant と別に破線・点線を指定します（`variant: muted, dash: dotted` で淡い点線）。`edges[].strands: 2–5` で経路に沿った平行線の束を描きます（構造化のみ）。凡例の `edge` の見本も両方を取ります。
- **集合のラベルと円柱**（#614）: `sets[].text` / `sets[].weight` で集合のラベルの大きさと太さを、`cylinder` の `props.capDepth` で蓋の深さを指定します。寸法を書いたノードの `geometry/label-overflow` のヒントには、収まる最小の寸法（確かめたもの）を添えます。入れ子の繰り返しは既存の書き方で表せるため、Skill に例を書きました。

## `sumi` テーマのパネル

- **パネルは白、枠は細く淡く**（[#608](https://github.com/nishide-dev/sumi-diagram/issues/608)、[#634](https://github.com/nishide-dev/sumi-diagram/issues/634)）: `sumi` / `sumi-dark` の既定と `muted` のグループをキャンバスの色（`sumi` は白、`sumi-dark` は紺）で塗り、枠を 0.5pt の淡い灰色（`sumi` #a9aebc、`sumi-dark` #6f7791）にしました。パネルが箱の一つではなく静かな領域として読め、色は意味を持つ要素だけが持ちます。テーマ自身の塗りで `geometry/color-on-panel` が出ることもなくなりました。砂色のパネルは `variant: filled`（1 つ）か `figure.themeOverrides.groupFill: "#efeddd"`（図全体）、従来の枠は `themeOverrides: {groupStroke: "#4e566b", frameWidth: 1pt}` で戻せます。
- **`geometry/color-on-panel` のヒント**（#608）: 示す変更で本当にパネルが白になるかを確かめ、tone を外す・variant を変える・`themeOverrides.groupFill` を書く、のうち効くものを示します。

## 互換性

- Figure Schema に次が加わりました（既存のプロパティの意味は、下の既定の変更を除いて変わりません）: `figure.layout.straighten` の既定 `true`、`edges[].lane`・`dash`・`strands`・`labelStyle`、`labelAt` の数、ノードの `iconAt`、`groups[].contentAlign`・`matchLabelHeight`、`arrange.sequence`、`sets[].text`・`weight`、`matrix` の `wrapHeaders`・`columnHeaderWidth`・`labelAt`・`rules`、`cylinder` の `capDepth`。
- **出力が変わる既定の変更**:
  - **`figure.layout.straighten` が既定で有効**（#620）: `straighten` を書かない構造化の図は配置が変わることがあります。コミット済みの作例・ギャラリー・Skill のベースレイアウト・README の図では変化はありませんでした。v0.19 の配置が必要なら `figure.layout.straighten: false` を書いてください。
  - **`sumi` / `sumi-dark` のパネルが白（キャンバス色）、枠が 0.5pt の淡い灰色**（#608、#634）: 既定・`muted`・`dashed`・`dotted`・`layers`・plane・tone 付きのグループの枠が変わります。`filled` の砂色、`filled-dashed` の枠、ノードの枠、凡例の枠、集合の輪郭は変わりません。`themeOverrides.canvas` を替えた図ではパネルもその色になります。
  - **減光（`dim: true`）したグループの枠は濃くしない**（#634）: 減光した枠は、元の枠のほうがキャンバスに対してコントラストが低ければ元の枠のままにします。すべてのテーマの規則で、`paper` の減光したパネルの枠も従来の #949494 から元の淡い枠になります（ギャラリーの dim の図）。ノードと線の減光は変わりません。
  - **直線・曲線の辺のラベルの既定の側**（#610）: `labelSide` を書かない `route: straight` / `curve` のラベルのうち、左向きの成分を持つ線と、ほぼ垂直の上向きの線のラベルが反対側へ移ります。直交のルーターが置くラベルは変わりません。
  - **`matrix` の `muted` のセルが淡い灰色**（#612）: セルと凡例の見本だけで、ほかの部品の `muted` は変わりません。
  - Skill のベースレイアウトとギャラリーの `sumi` / `sumi-dark` の図は、これらに合わせて再生成しました。
- **新しい lint**: warning の `geometry/avoidable-bend`・`geometry/edge-label-touches-line`・`layout/lane-blocked`・`layout/lane-bus-split`、info の `geometry/relocatable-node`・`geometry/content-band`・`geometry/edge-label-detached`・`geometry/icon-family-mix`・`geometry/icon-overuse` が加わり、既存の図に新しく出ることがあります。`geometry/theme-color-use` は中立の灰色の塗りをアクセントに数えなくなりました。作例 `dit-block` には `geometry/content-band` の info が 1 件増えます（図は変わりません）。
- `asset/icon-with-label` は構造化レイアウトでは出なくなりました（`icon` と `label` の併用が通ります）。
- 集合を含み、経路やラベルのはみ出しで全体が平行移動する図では、集合の輪郭がメンバーと一緒に動くようになりました（#630 で直した不具合。コミット済みの図には該当なし）。
- 論文の再現図（作例）の出力は変わりません（版の表記を除く。再現図のハッシュは更新していません）。
- 固定版 D2 は v0.9.0、同梱フォント・Tabler Icons・Fluent Emoji Flat・Takumi は v0.19.1 と同じです。
- 設計の判断は、[docs/design/decisions](https://github.com/nishide-dev/sumi-diagram/tree/v0.20.0/docs/design/decisions) の `604-avoidable-bends.md`、`605-icon-label-nodes.md`、`607-width-fitting.md`、`608-sumi-panel-fill.md`、`609-edge-lanes.md`、`610-edge-labels.md`、`611-catalog-sizes.md`、`612-matrix-headers.md`、`613-content-align.md`、`614-missing-parts.md`、`618-straighten-by-shifting.md`、`620-straighten-default.md`、`621-relocate-hint.md`、`630-sequence-diagrams.md`、`634-sumi-group-frames.md` を参照してください。
- **既知の制限**:
  - `straighten` は grid のセル・chat・傾いた平面の中を動かさず、ほかの線を悪くする移動は採りません（直らない線は `geometry/avoidable-bend` が知らせます）。有効な図では配置に少し時間がかかります。
  - 確かめたヒント（アンカー・移動・幅・`contentAlign`・ラベル・寸法）は 1 図あたりの試行回数に上限があり、大きな図や HTML・外部画像を含む図では一部を出しません。
  - シーケンス図の activation、参加者を下にも繰り返す表示、`alt` の else の区切り線はまだありません（`alt` は帯を 2 つ続けて書けます）。
  - `sumi` / `sumi-dark` では、減光した中身と `muted` のノード・線がほぼ同じ色です（[#636](https://github.com/nishide-dev/sumi-diagram/issues/636) で検討中）。
