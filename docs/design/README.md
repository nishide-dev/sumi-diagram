## 新しい設計判断の書き方

- 実装する issue ごとに `decisions/<issue番号>-<短い英語の名前>.md` を 1 つ作る（例: `decisions/350-edge-straight-route.md`）。issue 番号は一意なので、並行する PR が同じファイルや同じ番号を取り合わない。
- 本文は日本語。見出しは `# #<issue> <判断の題>` とし、次の項目を必要なだけ書く。
  - **背景**: 何が問題だったか。再現の手順や数値。
  - **決定**: 何をどう決めたか。契約（スキーマ・診断・出力）の変化。
  - **採らなかった案**: 理由とともに。
  - **互換性**: 出力が変わる図、変わらないことの確かめ方。
- コードや文書からは「設計 #<issue>」と書き、ファイルへリンクする。
- 1 つの issue で判断を見直すときは、同じファイルを更新する。別の issue で判断を変えるときは、新しいファイルに書き、古いファイルの先頭に新しいファイルへのリンクを足す。

## `phase1.md` の扱い

- §0〜§5 の基本契約は、契約そのものを変えるときに更新する。
- §6.1〜§6.101 は過去の判断の記録として残す。コードや文書が `§6.x` の番号で参照しているため、節を動かしたり番号を振り直したりしない。誤りの訂正以外では追記しない。
- 新しい判断を §6 に足さない。`decisions/` に書く。
