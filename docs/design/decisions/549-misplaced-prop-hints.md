# #549 置き違えたオプションと null のヒント

- **背景**: ノードに `height` を直接書くと、近い名前の `weight` を勧められた。matrix のセルの `text: ~` は「Invalid input」だけで、どのセルか分からなかった。
- **決定**:
  - 未知のフィールドが、その要素自身のコンポーネント（組み込み）の `props` のキーと**完全一致**するときだけ「`props` の下に書く」ヒントを出す。それ以外（`grop`、`eight` など）は従来どおり要素のフィールドから候補を選ぶ。コンポーネントが省略・組み込みでない（カスタム）ときは、`props` について何も主張しない。
  - `props` のユニオン（matrix のセルなど）の失敗は、型が合う枝の問題を報告する。入れ子のオブジェクトの未知キーは、その入れ子のキーから候補を選ぶ。
  - null のヒントは、そのフィールドが省略可能なときだけ「キーを省く」を勧め、必須なら「値を書く」と言う。
- **採らなかった案**: 全コンポーネントの `props` 名とのあいまい一致（別の意味のフィールドの打ち間違いを `props` に誘導してしまう）。カスタムコンポーネントの `props` の参照（検証のこの段階ではレジストリに届かない）。
- **互換性**: 診断のヒント文とパスが変わるだけで、受理する入力・出力は変わらない。
