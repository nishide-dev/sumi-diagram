# #609 ループ・skip・バスの線に通り道（lane）を指定する

## 背景

#603 の 10 枚のうち 5 枚で、ループ・skip・戻りの線を思う場所に通せず、隠れたジャンクションや余白で逃げた。

- 3-deep-crl: 残差の skip が破線の ×4 枠に沿って走り（`geometry/edge-on-border`）、`place` の箱に隠れたジャンクションを 2 つ置いて角を作った。
- 10-multi-agent-research: 「yes」のループをパネルの上に直交で出せず、`route: curve` は高く弧を描いて図が縦にはみ出した。代わりにグループの padding を全辺で広げ、パネルの下に空きができた。利用者への戻り線は、隠れたジャンクションの行を足して通り道を作った。
- 1-nsa: q_t は 3 つの注意すべてに入るが、バスの通り道を指定できず q_t → gate だけを描いた。

ルーターは費用最小の経路を選ぶので、「この線はこの側の、この距離に」という作者の意図を表す手段がなかった。

## 決定

### 書き方

```yaml
edges:
  - {from: c, to: a, lane: {side: north, offset: 5mm}}
  - {from: split, to: add, lane: {side: west, outside: unit}}
```

- `side`: `north | east | south | west`。issue の例は `left|right|top|bottom` だったが、アンカー（`fromAnchor: west`）と同じ語にそろえた。
- `offset`: 長さ（`"4mm"` など）。省略時は 6pt。矢じりのある線では、矢じりの長さ＋角の半径（1pt の線で 10pt）のほうが長ければそれ。
- `outside`: グループかノードの ID。省略時は両端。
- structured のみ。auto では `layout/structured-only`（error）。

### 通り道の位置（`src/layout/route/lanes.ts` の `planLanes`）

- 基準の箱（両端、または `outside` の枠）の `side` 側の面のうち最も外側から、`offset` だけ外の線。`outside` がグループで、題が枠の外（`labelAt: above-left` など）のその側にあれば、題も基準に含める。
- 各端の付く側: その側の面が通り道より内側なら `side`。端全体が通り道より外にあれば、通り道に向いた反対側（バスの源が通り道の外にある場合）。ジャンクションは中心から。通り道が端を貫くときは問題として扱う（下記）。
- **バス**: 同じ側の lane を持ち、源（または先）を共有する辺は推移的に 1 つにまとめ、通り道はそのうち最も外側の 1 本にする。同じ源の同じ側の既定の点から出るので 1 つのネットになり、幹を共有する（既存のネットの仕組みをそのまま使い、新しい束ね処理は作らない）。列に並んだ先の横に幹を通すには、各辺に `outside: <その先>` を書く。
- 幹を共有するのは、共有する端が同じ点に解決されたときだけ（ルーターのネットは端の点で決まる）。同じ源でもアンカーが違う（`east:0.3` と `east:0.7`）など、点が分かれたバスは `layout/lane-bus-split`（warning）で「幹を共有しない」と言う。どの lane も同じ線の上には描く。アンカーを黙って捨てて点をそろえる案は、作者の書いたものを無視するので採らなかった。
- 位置は配置後の幾何だけで決まる純粋な計算で、端の解決（`resolveEnds`）とルーターの両方が同じ関数を呼ぶ。端の解決では、lane の側を「アンカーなしの側」として渡す（同じ側のアンカーは位置を保つ。既定の分配や #113 の分離はそのまま効く）。`padding.ts`・`straighten.ts` も `resolveEnds` を通るので、同じ端を見る。

### 描き方（`router.ts` の `#laneRoute`）

- lane の辺は、ほかの辺より先に、探索せずに描く: 源の点から通り道まで真っすぐ、通り道に沿って、先の点まで真っすぐ。通り道の座標を格子線に加える。作者が決めた経路なので、費用の比較はしない。
- 描けない理由があれば描かず、`layout/lane-blocked`（warning）で理由を言い、その辺はふつうに配線する（lane の側の端はそのまま）。理由:
  - ノード・ジャンクションを通る、または沿う（格子の通行止めと同じ判定。名前を挙げる）
  - グループの題・キャプションを通る
  - グループの枠の上を走る（`offset: 0` の `outside` など）
  - ほかの辺の経路（予約済みの stub を含む）に沿う
  - 端からの直線が stub（クリアランスと矢じり）より短い
  - 通り道が端を貫く、別の側のアンカー、`straight` アンカー、一方の端がもう一方を含む、zoom の辺、固定点のある部品
- 描いた lane の経路は、平行な線の分離（`separateParallelRuns` / `separateSameSideRuns`）で動かさない（`fixed`）。ほかの辺は、先に描かれた lane を占有として避ける。それでも lane の平行な区間から線の間隔（線幅の半分ずつ＋1.5pt）未満・3mm 以上並ぶ線は、最後に `keepClearOfLanes` で動かせる側（向き合う 3 区間の線の中央、同じ側の skip の区間）を、間隔だけ離れた最も近い位置へ移す。ノード・グループの枠・lane を越える移動や、ほかの線を混ませる移動はしない。lane は不動の障害物として扱う。
- **描いた経路で確かめる**: `routeEdges` の最後（直線・zoom を足し、内容の平行移動も済んだ配置）で、配置から通り道を計算し直し、各 lane の辺の経路の端以外の点がすべて通り道の上にあるか（端がそろったバスの枝は通り道を横切る 1 本の直線）を見る（`laneDiagnostics`）。外れていて、まだ lane-blocked / no-route が出ていなければ `layout/lane-blocked` を出す。幾何の推測ではなく、実際の経路を見る。lane を黙って無視することはない。

### ほかの仕組みとの関係

- `geometry/avoidable-bend`・`geometry/relocatable-node`: lane の辺は対象外。曲がりは作者が求めたもので、避けられる曲がりではない。lane なしで同じアンカーの辺には avoidable-bend が出て、lane を付けると出ないことをテストで確かめた。
- `figure.layout.straighten`: lane の辺はそろえる対象にしない（扇の数には入れる）。
- 立方体の面の直線（#587、`faceDirect`）: lane の辺は対象外。
- 検査段階: `route` との併用・自己ループ・セルの端は `layout/invalid-lane`（error）、知らない `outside` は `layout/unknown-lane-outside`（error）。

### 出力

lane は opt-in で、書かない図の経路・SVG・PDF はバイト単位で変わらない（既存のゴールデンと全テストが通る）。lane のない図では `planLanes` は空を返し、追加の格子線も診断もない。

## 検討して採らなかった案

- **A\* の費用で通り道に寄せる**: 通り道の外に罰を与える、通り道の上を安くする、など。費用の釣り合いで結果が変わり、「指定どおりか」を約束できない。描けないときの理由も言えない。
- **経由点（隠れたジャンクション）を自動で置く**: #603 の回避策そのもので、ネットの結合（ジャンクションに触れる辺は 1 ネット）と矢じりの規則が絡む。
- **バス専用の書き方（`bus: <id>`）**: 既存のネットの共有で幹はできるので、通り道の位置を決めれば足りる。同じ源・同じ側の lane をまとめる規則で済ませた。
- **通り道の基準を「通り道の外にある端を除く」で自動に決める**: 戻り線（右下の源から左上の先へ、下を回す）では、源が先より下にあるため基準から外れ、通り道が図の中を横切る。基準は両端か `outside` の明示に限った。
