# #604 避けられる曲がりを lint で知らせ、直し方を示す

- **背景**: #603 の試用（10 枚）で、矢印の無駄な S 字・階段・枠沿いが残っていた。利用者が挙げたのは 3 例。(1) 3-deep-crl の Encoder φ → Critic 行列: `toAnchor: "east:0.2"` が φ の辺の範囲から 0.5mm 外れていて S 字。(2) 同じ図の h_i → 分岐ジャンクション: 2.5mm の横ジョグと、スキップ線が枠から 4〜6mm で 60〜80mm 沿う。(3) 6-deepseek-v4 の Router → routed experts: 4 回曲がり、1.5mm と 1.96mm の小さな段。既存 lint（`edge-jog` は 1pt 未満、`edge-on-border` / `edge-near-*` は 1.5pt 以下）はどの例も拾わなかった。
- **決定**: **`geometry/avoidable-bend`**（warning、`src/lint/geometry/avoidable.ts`、structured のみ）を足す。経路は変えず、原因と書き手が書ける直し方を示す。
  1. **書いたアンカー**: 向かい合う辺が共通の範囲を持つのに、アンカーの位置が範囲の外、両端のアンカーが違う位置、またはアンカーが 1 つで相手の端の位置から 1pt を超えてずれている。ヒントにアンカーの値を示す。アンカーのない相手の端がすでに共通の範囲にあれば、書いた端の値 1 つ（ルーターが 1pt 以内のずれを揃える #169 の範囲で、相手の端の位置に合わせる）。そうでなければ両端の値（同じ座標に乗る 2 つ）。値は小数 2 桁、なければ 3 桁、4 桁の順に探し、**その値が実際に表す座標の線**がほかのノード・見出しのクリアランスを保つもののうち、書かれた位置に最も近いものを選ぶ。そのような値がなければ真っ直ぐのヒントは出さない。真っ直ぐが無理で L 字が通るなら、辺を移す端のアンカーを示す（例 `fromAnchor "east"`）。これは**両端にアンカーが書いてあるときだけ**: 辺を保つ端は書いた位置のまま、移す端はその辺の中央として、その L 字の線を確かめる（移る辺をほかのエッジが使っていないこと）。アンカーのない端は、相手が辺を変えると扇形の合流やポートの分け方で位置が変わりうるので、確かめられない L は示さない。例 1 は φ の中心が範囲の外なので両端の値を示し、適用すると一直線になる（テストで確認）。角のアンカー（0 / 1。ズームの囲み線などの意図的な形）、ジャンクション端、共有ポートは対象外。
  2. **階段**: 向かい合う端の間で 3 回以上曲がり、1pt 以上 4mm 未満の段があり、**2 回曲げの経路（中間の線を両端のスタブの間の 33 の位置に置く）がどれもほかのノード・見出しのクリアランスに入る**とき、それらを塞ぐノード（多くは付属ラベル）を名指しする。どれか 1 つでも通れば出さない。例 3 は `node "hash-note" and node "experts-label"`。どちらを動かしても Z になる（hash-note を南へ、experts-label を北へ。テストで確認）。
  3. **小さな段**: 曲がりの間の 1pt 以上 2mm 未満の線分（1pt 未満は従来どおり `edge-jog`）。扇形・扇形の合流・多重辺の枝（ジャンクションの端、またはほかのエッジと要素の同じ辺を共有する端）は、群の形の一部なので対象外。
  4. **ジャンクション直前の折れ**: ジャンクションへ入る線が 4mm 未満の横の段で終わり、ジャンクションから同じ軸で別の線が出ている（幹を少し外している）。例 2 の h_i → split。
  - ヒントの末尾で `figure.layout.straighten: true`（#618。ノードを余裕の範囲で動かして線を揃える）にも触れる。
  - **既存ルールの閾値は変えない**: 例 2 のスキップ線は枠から 4〜6mm で群の余白。1.5pt 以下を「枠の一部に見える」とする `edge-on-border` / `edge-near-border` には当たらないのが妥当。
- **採らなかった案: 配線後に経路を書き換える**。PR #617 では最初、配線の後に線を単純化する処理（自由な端をずらして一直線・L 字・Z 字にする、段をずらす）も入れたが、利用者と相談して**取り下げた**。理由:
  - 効果が小さかった。#603 の 10 枚で、利用者のレビューを反映して安全な範囲に絞った版が変えた線は 1 本だけ（8-kimi-k2 の sft → infer）。
  - 境界の不具合が続いた。扇形の枝の揃いを崩す（再現図 llama4-moe）、角の丸めが効かない短い Z（例 3）、後の端が先に使われた辺を取る、直線・曲線・ズームの線と交わる、平行区間の分離のあとで照合とずれる、などをレビューのたびに直す必要があった。
  - 利用者が望む方向は、端のノードを動かして線を揃えること。これは `figure.layout.straighten`（#618）で入り、そちらを推奨する。
  - lint の安全確認（ヒントの値が表す線そのものを、ノード・見出しのクリアランスで確かめる）は残した。
- **3 例**:
  1. **φ → Critic — lint のヒントで直る**: 両端のアンカーの値を示し、書けば一直線。
  2. **h_i → 分岐とスキップ — lint で知らせる**: 2.5mm の折れを知らせ、h_i と分岐を揃えるよう示す。スキップの枠からの距離は配置（ジャンクションの `place` と余白）で決まる。
  3. **Router → experts — lint で知らせる**: 2 つの付属ラベルを名指しする。どちらを動かしても Z になる（テストで確認）。
- **この PR は #604 の一部**（lint とヒント）。配線そのものを揃える解決は #618（`figure.layout.straighten`）。
- **互換性**: 出力（例・ギャラリー・再現図・golden・Skill のプレビュー）は main とバイト一致。新しい warning が出る既存の図は期待に加えた: 重ねた群（`props.layers`）の例（入力の中心が前面の枠の中心から外れ、`west` に値を示す。群の端は前面の枠で測る）、fill の fixture（1.6mm の段）、#167 の図 C（アンカーが一直線を外す線、ヒント付き）、#127 の見出しを避ける例（0.4mm の段）、#124 の下書き（離れたアンカー）。
