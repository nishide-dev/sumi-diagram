# #604 避けられる曲がりと被りを配線後に取り除き、残りを lint で知らせる

- **背景**: #603 の試用（10 枚）で、矢印の無駄な S 字・階段・枠沿いが残っていた。利用者が挙げたのは 3 例。(1) 3-deep-crl の Encoder φ → Critic 行列: `toAnchor: "east:0.2"` が φ の辺の範囲から 0.5mm 外れていて S 字。(2) 同じ図の h_i → 分岐ジャンクション: 2.5mm の横ジョグと、スキップ線が枠から 4〜6mm で 60〜80mm 沿う。(3) 6-deepseek-v4 の Router → routed experts: 4 回曲がり、1.5mm と 1.96mm の小さな段。グリッド探索（A\*）は `resolveEnds` が決めたポートのまま、格子上で最も安い経路を選ぶので、ポートを辺に沿ってずらせば真っ直ぐになる場合や、クリアランス域・ラベルのコストで小さな段が 2 つ並ぶ場合を直せない。既存 lint（`edge-jog` は 1pt 未満、`edge-on-border` / `edge-near-*` は 1.5pt 以下）はどの例も拾わなかった。
- **決定**:
  - **配線後の単純化**（`src/layout/route/simplify.ts`、`Router.#simplify`）。全エッジを配線したあと、平行区間の分離（#329・#512）の前に、文書順に 1 本ずつ次を試す。
    1. **真っ直ぐ**: 向かい合う辺の範囲が重なれば、自由な端（YAML にアンカーがない端）を辺に沿って動かして一直線にする。#169（`STRAIGHTEN_TOLERANCE` = 2 unit 以内を配線前に揃える）を、配線後に範囲の重なり全体へ広げたもの。#169 の前処理はグリッドの都合で残す。両端が自由なら重なりの中央、片方が固定ならその位置に合わせる。
    2. **L 字**（1 回曲げ）: どちらの角でも。自由な端は、その要素の**ほかのエッジが使っていない辺**へ移れる。
    3. **Z 字**（2 回曲げ）: 向かい合う現在のポートの間で、中間線を通路内の 17 点から、ノード・文字・描かれた枠・他の線から最も離れる位置に置く。
    4. **ずらし**（曲がり数は同じ）: 上で減らせないとき、曲がりと曲がりの間の線分を隣の線分が許す範囲で平行移動し、2mm 未満の段をなくす・ノードのクリアランスへの食い込みを減らす・枠やノードや他の線に 1.5mm 以内で 3mm 以上沿う区間を離す。U ターンの中間は内側にしか動かさない（線を長くしない）。群の枠をまたいで動かさない。
    - 置き換えるのは、曲がりが減るとき、または同じ曲がりで小さな段・食い込み・沿いが減るときだけ。候補は**元の経路と比べて、相手ごとに**悪くしないものだけ（レビューで合計の比較から改めた）: 障害物（端以外のノード、群の見出し、キャプション）ごとに、元の経路がクリアランスを保っていたものはクリアランス内に入らず、元から近すぎたものはそれ以上近づかない。他の網の線ごとに、交差・接触・重なり・近接（クリアランス未満の平行）の回数が元を超えない（元が交わっていない線とは交わらない）。群ごとに、枠をまたぐ回数と描かれた枠に沿う区間が元を超えない。さらに、端のスタブ（クリアランスと矢頭）と矢頭前の余白（まず全長、取れなければ元の経路が保っていた分まで）、端の要素に入らない、他の線の矢頭前の余白を横切らない。
    - **対象**: 自分だけの網（ジャンクションも共有ポートもない）で両端がポート、自己ループでなく入れ子でないエッジ。加えて、ジャンクションと「ほかのエッジが使わないポート」を結ぶ線は、ポートを辺に沿って動かす真っ直ぐだけを試す（扇形の分岐で、目標が幹から少しずれた小さな折れを消す）。
    - **動かせる端**: アンカーなし、形が `rectangle` / `square` / `text`（`cylinder` は東西の辺だけ）、描画器・画像レイヤー・凡例・tokens/matrix のセル・キャプションでない、分割体の唇補正（#246）がない。`fanIn: spread` で並べた端は動かさない。同じ辺のほかの端からは 2 クリアランス離し、順序を入れ替えない。
    - **辺の変更**（L 字のための別の辺）は、経路が 3 回以上曲がる・2mm 未満の段がある・沿っている・クリアランスに食い込んでいるときだけ。普通の S 字はアレンジ木が決めた辺（#134）を保つ（行の中のノードへ下から入るような変化を避ける）。
    - 傾いた平面の中（#577）は平面座標で配線して写像するため、今回は単純化しない（`RouteOptions.simplify: false`）。
    - **注記の文字のそば**: 上で曲がりを減らせないとき、注記の文字（ノードに付けた `label`、キャプション）だけは、ボックス全体ではなく**各行の幅の箱**から 1.5pt（通常の半分）のクリアランスで通してよいとして、もう一度だけ真っ直ぐ・L・Z を試す。文字には決して触れない（相手ごとの規則も同じ）。中央揃えの 2 行目が短い注記の横を、列が通れるようになる。例 3 はこれで Z になった。
  - **`geometry/avoidable-bend`**（warning、`src/lint/geometry/avoidable.ts`、structured のみ）。ルーターが動かせない理由を名指しする。
    1. **書いたアンカー**: 向かい合う辺が共通の範囲を持つのに、アンカーの位置が範囲の外（または両端のアンカーが違う位置）。片方だけ書いてあれば、一直線になる値（書かれた位置に最も近い範囲内の値、2 桁）を示す。例 1 は `Write toAnchor "east:0.15"`。アンカーのない相手の端はルーターが揃える。両方書いてあれば、**同じ座標に乗る 2 つの値**（2 桁で乗る組、なければ 3 桁、4 桁）を示す。真っ直ぐが無理で L 字が通るなら辺を示す（`fromAnchor "east" and toAnchor "north"`）。角のアンカー（0 / 1。ズームの囲み線などの意図的な形）、ジャンクション端、共有ポートは対象外。
    2. **小さな段**: 曲がりの間の 1pt 以上 2mm 未満の線分（1pt 未満は従来どおり `edge-jog`）。
    3. **階段**: 向かい合う端の間で 3 回以上曲がり、1pt 以上 4mm 未満の段があり、端の間の帯にノードが立っている。そのノード（多くは付属ラベル）を名指しする。例 3 で注記が両方の列を塞ぐ場合（テストでは 2 行目を長くした）にこれが出る。
    4. **ジャンクション直前の折れ**: ジャンクションへ入る線が 4mm 未満の横の段で終わり、ジャンクションから同じ軸で別の線が出ている（幹を少し外している）。例 2 の h_i → split。ジャンクションから出る扇形の段や、バスの端に合流する角は対象外。
  - **既存ルールの閾値は変えない**: 例 2 のスキップ線は枠から 4〜6mm で、群の余白そのもの。1.5pt 以下を「枠の一部に見える」とする `edge-on-border` / `edge-near-border` の定義は妥当で、例 2 では出ないのが正しい。例 3 の段は単純化でなくなった。

- **3 例**（どれが自動で直り、どれが lint のヒントで直るか）:
  1. **3-deep-crl φ → Critic（lint のヒントで直る）**: 書いたアンカー `east:0.2` が φ の範囲の外にあり、ルーターはアンカーを動かさないので S 字が残る。lint が `Write toAnchor "east:0.15"` を示し、適用すると一直線になる（φ 側の端が範囲内へ動く。テストで確認）。
  2. **3-deep-crl h_i → 分岐とスキップ（lint で知らせる。配線では直らない）**: h_i のラベルと分岐ジャンクションが 2.5mm ずれているのは配置の問題で、lint が両者を揃えるよう示す。スキップ線の 4〜6mm は群の余白とジャンクションの `place` で決まり、配線では動かさない。
  3. **6-deepseek-v4 Router → experts（自動で直る）**: 4 回曲がり・段 1.5mm と 1.96mm だった線が、注記の行のそばを通る規則で **Z（2 回曲げ）** になった。縦線は「hash routing」の行と「384 routed experts…」の行の両方から 1.5pt 以上離れ、文字には触れない。注記が全部の列を塞ぐ場合（2 行目が長いとき）は、段を 2mm 以上に広げた階段になり、lint が塞いでいるノードを名指しする。
- **性能**: 合成 100 ノード図（router.test.ts）で、grid 350 → 約 380ms、`fanIn: spread` 456 → 約 560ms、columns はほぼ不変。交差点数・接触数は変わらない（1170、10）。経路と端の箱の周囲だけを見る、他の線の箱で先に除外する、比較中の候補が元より悪くなった時点で打ち切る。
- **採らなかった案**:
  - グリッド探索のコストを変える（曲がりのコストを上げる、クリアランス域を安くする）: すべての図の経路が変わり、#116・#217・#512 の調整を崩すため。後処理なら対象を限定でき、出力の変化を確かめやすい。
  - 書いたアンカーを好みとして扱い動かす: アンカーは位置の指定として意味を保つ。lint が値を示す。
  - ジャンクションを動かす・枠の余白を詰める（例 2 のスキップ）: 配置の変更で、ほかの線の形も変える。`junctionsOnBus`（#385）の範囲外。
  - 普通の S 字でも L 字にする: 行やスタックの流れの向き（#134 のアレンジ木の辺）を崩すため、問題のある経路に限った。
- **互換性**: 図の出力が変わるのは、ルーターが単純化した線だけ。リポジトリの例・ギャラリー（490 ファイル）では `examples/llama4-moe`（再現図）の 1 本（Router の分岐 → Expert 1）だけで、3.3mm の折れが消えて一直線になった（曲がりの除去のみ）。再現図のハッシュは YAML のハッシュなので変わらない。golden は同じ図の PPTX 2 件と Skill のプレビュー 1 枚。角のアンカー（0 / 1）を書いた線は、lint と同じく意図した形として単純化しない。テストの期待を変えたもの:
  - #169 の S 字: アンカーのない端は配線後に一直線になる（両端アンカーの S 字のテストを別に残した）。
  - #134 の付属ノードの辺: 間隔の狭い S 字が node a に沿っていたため L 字になった。間隔を広げて辺の選び方の検査を保った。
  - `layout/group-title-offset` の例（テストと Skill の structured.md）: アンカーのない端がずれて一直線になり、折れが出ない。テストはアンカー付きにし、Skill の記述を直した。
  - #167 の図 C: 1pt 未満の段が消えた。
  - #127 の見出しを避ける例: 見出しの右端を回る階段が、c の空いている東の辺への L 字になり、文字に触れなくなった（`edge-touches-label` が消えた）。
  - 新しい warning が既存の fixture・下書きで出るもの（fill の 1.6mm の段、#124 の下書きの離れたアンカー）は期待に加えた。
