# #604 避けられる曲がりを lint で知らせ、安全なものだけ配線後に取り除く

- **背景**: #603 の試用（10 枚）で、矢印の無駄な S 字・階段・枠沿いが残っていた。利用者が挙げたのは 3 例。(1) 3-deep-crl の Encoder φ → Critic 行列: `toAnchor: "east:0.2"` が φ の辺の範囲から 0.5mm 外れていて S 字。(2) 同じ図の h_i → 分岐ジャンクション: 2.5mm の横ジョグと、スキップ線が枠から 4〜6mm で 60〜80mm 沿う。(3) 6-deepseek-v4 の Router → routed experts: 4 回曲がり、1.5mm と 1.96mm の小さな段。既存 lint（`edge-jog` は 1pt 未満、`edge-on-border` / `edge-near-*` は 1.5pt 以下）はどの例も拾わなかった。
- **利用者の判断（PR #617 のレビュー）**: 最初の版はルーターが積極的に線を単純化したが、次の 2 点が受け入れられず、範囲を絞った。
  - 再現図 `examples/llama4-moe` で、扇形の分岐の 1 本（Router → Expert 1）が一直線になった。元の図は分岐がそろって同じ小さな段の形をしており、1 本だけ直すと形の揃いが崩れる。再現図は main とバイト一致でなければならない。
  - 例 3 を Z にした版は、線分が短く、テーマの角の丸め（半径 4pt）がほとんど効かず角張って見えた。
  - 利用者が望む方向は、端のノード・群をレイアウトの段階で動かして線を揃えること。これは #618 で扱う。**この PR（#617）は #604 の一部**（lint と保守的な配線後の単純化）で、3 例の配線そのものの解決は #618 に残る。
- **決定**:
  - **`geometry/avoidable-bend`**（warning、`src/lint/geometry/avoidable.ts`、structured のみ）。ルーターが直さない原因を名指しする。
    1. **書いたアンカー**: 向かい合う辺が共通の範囲を持つのに、アンカーの位置が範囲の外（または両端のアンカーが違う位置）。ヒントに一直線になる値を示す。片方だけ書いてあればその値、両方なら**同じ座標に乗る 2 つの値**。値は小数 2 桁、なければ 3 桁、4 桁の順に探し、その値が実際に表す座標の線がほかのノード・見出しのクリアランスを保つもののうち、書かれた位置に最も近いものを選ぶ。そのような値がなければ真っ直ぐのヒントは出さない。真っ直ぐが無理で L 字が通るなら辺を示す（`fromAnchor "east" and toAnchor "north"`）。例 1 は `Write toAnchor "east:0.15"` で、適用すると一直線になる（テストで確認）。角のアンカー（0 / 1。ズームの囲み線などの意図的な形）、ジャンクション端、共有ポートは対象外。
    2. **階段**: 向かい合う端の間で 3 回以上曲がり、1pt 以上 4mm 未満の段があり、端の間の帯にノードが立っている。そのノード（多くは付属ラベル）を名指しする。例 3 は `node "hash-note" and node "experts-label"`。
    3. **小さな段**: 曲がりの間の 1pt 以上 2mm 未満の線分（1pt 未満は従来どおり `edge-jog`）。扇形・扇形の合流・多重辺の枝（ジャンクションの端、またはほかのエッジと要素の同じ辺を共有する端）は、群の形の一部なので対象外。
    4. **ジャンクション直前の折れ**: ジャンクションへ入る線が 4mm 未満の横の段で終わり、ジャンクションから同じ軸で別の線が出ている（幹を少し外している）。例 2 の h_i → split。
  - **配線後の単純化は保守的に**（`src/layout/route/simplify.ts`、`Router.#simplify`）。全エッジの配線後、平行区間の分離（#329・#512）の前に、文書順に 1 本ずつ、真っ直ぐ（自由な端を辺に沿ってずらす。#169 の一般化）→ L 字 → Z 字を試し、減らせなければ曲がりの間の線分をずらして 2mm 未満の段・食い込み・枠沿いを減らす。ただし次に限る。
    - **対象**: 自分だけの網で両端がポート、**両端とも要素のその辺をほかのエッジと共有しない**エッジ（`route: straight` / `curve`・ズームの線の端も、その辺を使うものとして数える）。扇形（同じ辺から出る・入る線）、扇形の合流、`fanIn: spread`、ジャンクションの扇、多重辺は触らない（揃った枝の形を保つ）。自己ループ、入れ子、角のアンカーを書いた線、傾いた平面の中も触らない。
    - **角の丸め**: 候補のすべての角が配線の角の半径（`WIRE_CORNER_RADIUS`）をそのまま取れること。描画（`render/wire.ts`）と同じく、角の両脚が半径の 2 倍以上（端の脚は矢頭の分を足す）、角の弧を描く正方形がどの障害物にも触れない。満たさない候補は取らない（例 3 の Z はここで退けられ、元の階段のまま）。
    - **元の経路と比べて相手ごとに悪くしない**: 障害物（端以外のノード、群の見出し、キャプション）ごとに、元が保っていたクリアランスは保ち、元から近すぎたものにはそれ以上近づかない。他の網の線ごとに交差・接触・重なり・近接の回数が元を超えない（元が交わっていない線とは交わらない）。`route: straight` / `curve`・ズームの線（曲線は折れ線にして）も、線ごとに元より多く触れない。これらは配線の後の経路で描き（ジャンクションへの曲線は、そこの直交経路から接線を取る）、単純化のあとに最終の経路で描き直して、どれかに元より多く触れる置き換えは取り消し、それを除いてやり直す（3 回まで。収まらなければ何も置き換えない）。群ごとに枠をまたぐ回数・枠沿いが元を超えない。端のスタブと矢頭前の余白、他の線の矢頭前の余白も守る。
    - **動かせる端**: アンカーなし、形が `rectangle` / `square` / `text`（`cylinder` は東西の辺だけ）。別の辺へ移るのは、経路が階段・小さな段・沿い・食い込みのときで、移り先はほかのエッジが使っていない辺だけ。普通の S 字はアレンジ木の辺（#134）を保つ。文書順に処理し、端を動かすたびに辺の使用状況を更新して、後の端はその時点の空きから選ぶ。
    - 注記の文字（付属 `label`・キャプション）のそばは、通常のクリアランスで曲がりを減らせないとき、各行の幅の箱から 1.5pt で通してよいとしてもう一度試す（文字には触れない。角の丸めの規則は同じ）。
  - **既存ルールの閾値は変えない**: 例 2 のスキップ線は枠から 4〜6mm で群の余白。1.5pt 以下を「枠の一部に見える」とする `edge-on-border` / `edge-near-border` には当たらないのが妥当。
- **3 例（どれが自動で直り、どれがヒントで直るか）**:
  1. **φ → Critic — lint のヒントで直る**: ルーターはアンカーを動かさないので S 字が残る。lint の `toAnchor "east:0.15"` を書けば一直線。
  2. **h_i → 分岐とスキップ — lint で知らせる**: 2.5mm の折れを lint が知らせ、h_i と分岐を揃えるよう示す。スキップの枠からの距離は配置（ジャンクションの `place` と余白）で決まる。どちらもレイアウト段階で端を動かす別 Issue の対象。
  3. **Router → experts — lint で知らせる（配線は元のまま）**: 2 つの付属ラベルの間を通る Z は角が丸まらないため取らない。lint が 2 つのラベルを名指しし、どちらかを動かせば（テストでは hash-note を南へ）Z になる。

- **採らなかった案**:
  - 扇形の 1 本だけを直す・角を半径より小さく丸める候補を取る: 利用者の判断で不可（枝の揃いと丸めを優先）。
