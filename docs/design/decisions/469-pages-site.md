# #469 GitHub Pages サイト

## 背景と方針

README、図の作例、コンポーネントの見本、エージェント向けの依頼文を日英で閲覧できる静的サイトを用意する。既存の nishide-dev.github.io と一貫する cream・navy・sand、文字組み、細い罫線を採用する。

追加のフレームワークやランタイム依存を避け、Bun の HTML バンドラ、vanilla TypeScript、CSS を使う。プロンプトの組み立ては DOM に依存しない純粋関数とし、日英の文章をテストする。

## 決定

ギャラリーのカタログと描画ジョブを再利用し、全テーマとパレットの組合せをビルド時に SVG として生成する。データと SVG は相対 URL で配信し、実行時の描画や巨大な埋め込みデータを不要にする。YAML Document API でテーマ・プロファイル・パレットを反映し、既存の上書きとコメントを維持する。描画エラーはビルドを失敗させる。

examples はコミット済み SVG と YAML を使用し、冒頭コメントにある論文 URL と少数の補完 URL を公開する。research/ と private figures は除外する。

`site/index.html`、`styles.css`、`app.ts`、`i18n.ts` で画面を構成し、ハッシュで 4 ページを切り替える。テーマとパレットは `data.json` から取得し、個別 SVG を遅延読み込みする。表示する YAML はビルド時と同じ `site/source.ts` で生成する。プロンプトは `site/prompt.ts` の純粋関数を共有する。バンドルの圧縮展開ではなく個別ファイルを使うことで、必要な図だけを取得できる。

## 互換性

既存の CLI や図の出力は変更しない。デプロイは #470 で扱う。

## 型と画面幅

### 背景

Examples のハッシュが一覧要素の ID と衝突し、ブラウザが初期表示時に一覧へスクロールしていた。狭い画面ではグリッドの子要素の最小幅がコンテンツ幅に引っ張られていた。

### 決定

ルート名と一覧の ID を分け、ハッシュナビゲーションで見出しを飛ばさない。グリッドとフレックスの子要素を縮小可能にし、長いコードは個別のスクロール領域に収める。DOM の必須 ID は欠落時に例外を出し、イベントとデータの型を TypeScript で検査する。

### 互換性

URL のハッシュ、サイトの機能、CLI と図の出力は変わらない。

## レビュー対応

### 決定

カタログの説明は文字列全体を HTML エスケープし、属性のない `code` タグの組だけを復元する。選択ボタンは言語変更時以外は再生成せず、押下状態だけを更新してキーボードフォーカスを保つ。自由記述の入力名とフィールド名は日英で提供する。

画像見本に必要なファイルをサイトのビルドに同梱し、見本の下にダウンロードリンクを置く。YAML と同じディレクトリに保存すれば相対パスを解決できる。

### 互換性

サイトの表示と配布ファイルのみを変更し、CLI や図の形式は変更しない。
