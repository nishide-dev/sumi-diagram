# #492 集合の重なり色

## 背景

集合の不透明な淡色を積で重ねる従来の描画は、重なりが暗く濁って見える。原図の色を保つ用途には従来の描画も必要である。

## 決定

`figure.setOverlap` を図全体の既定、`sets[].overlap` を個別の上書きとし、`mix` と `multiply` を受け付ける。省略時は `mix`。異なる指定の集合が交差するときは `multiply` を優先し、その領域の従来の色を保つ。塗りのない集合は重なりの色に参加しない。

`mix` は各色の OKLCH の明度と彩度を平均し、色相は等重みの円平均とする。ほぼ無彩色の色相は不定なので平均から除く。明度は明るい地で 0.05 下げ、暗い地で 0.05 上げる。3 色以上も同じ式で求め、領域は不透明に塗る。SVG、PDF、画像・編集可能 PPTX と幾何 lint は同じ色を使う。混色による意図的な色相・彩度の変化を泥濁の警告とはしない。

5 個以上の共通領域も参加する全色と指定を使う。交差の次数を制限せず、小さい組から順に描くため、全組が重なる場合の領域数は指数的に増える。意図的な混色自体を入力色と比較して警告せず、混色後の色を基準にカーキ色や上からの半透明塗りによる濁りを検査する。`multiply` は従来どおり入力色との彩度差だけを検査する。

## 互換性

塗りのある集合の重なりは既定で変化する。従来の色が必要なら `figure.setOverlap: multiply` または各集合の `overlap: multiply` を指定する。TriCL の集合は塗りがないため色は変化しない。コミット済み examples の SVG には塗られた集合の重なりがない。全テーマ・全形式での互換性比較は未完了である。
