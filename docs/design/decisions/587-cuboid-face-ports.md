# #587 cuboid の既定のポートを「面の中心から面の中心へ」にする

- **背景**: #575 の既定（`ports: center`）は、立体の 3D の中心へ向けた線がシルエットと交わる点に着く。隣り合う cuboid の線は、出る側ではシルエット（側面の外側の辺）から出るので、出る面の中心から出ているようには見えない（サイトの `sumi/cuboid`）。利用者の要望は「出る面の中心から入る面の中心へ向けて引く。これを既定にする」。
- **決定**:
  - **既定を `ports: face` にする**。書いたアンカーのない端は、相手の中心が向く側（東西南北。従来と同じ選び方）の面の中心 = 3D の重心を使う。東 = 側面（見える）、北 = 上面（見える）、西 = 左面（前面の後ろに隠れる）、南 = 底面（隠れる）。左面の重心は `(fx + dx/2, 前面の中央の高さ − dy/2)`、底面は `(fx + w/2 + dx/2, 前面の下辺 − dy/2)`。東・西の面の重心は外接形の中央の高さ（= 3D の中心と同じ高さ）にあるので、`align: center` の行では隣どうしの線が水平になる。
  - **線は面の中心どうしを結ぶ 1 本の直線**。直交ルーターの端にはせず、IR で `route: straight` として #349 の直線ルート（`layout/route/diagonal.ts`）で描く（#584 のブロック端と同じ経路）。矯正のスライドはしない（利用者の希望: 面の中心どうしを結ぶ）。見える面の端は面の中心を線の端にし、自分の面の上の区間は上に描く（`ports: face` の従来の描き方と同じ。矢じりは面の中心に載る）。隠れた面の端は、その面の中心を狙い、シルエットと交わる点で止める（線は立体の上を描かない。矢じりはシルエットに載る）。契約は `OutlineDrawing.hiddenFaceContacts`（`west` / `south` の重心）を足した。
  - **立体でないノードとの線**: cuboid 側が面の中心、もう一方は従来の接点を、cuboid の面の中心から相手の中心へ向かう線上に取る（#585 のブロック端と同じ向きの揃え方。相手の端の「狙う点」を面の中心にする）。
  - **直線にする条件**: IR は条件を満たす辺に `faceDirect` を付ける（どちらかの端が `ports` が `center` でない cuboid で、両端がノードで自分自身でなく、`route`・`fromAnchor`・`toAnchor`・ブロック端がなく、`figure.layout.fanIn` を書いておらず、同じ 2 ノードを結ぶ別の線がなく、cuboid が傾けた平面の中にない）。配置のあと（`render.ts` と `layoutStructuredFigure`）に `resolveFaceRoutes`（`layout/route/face-routes.ts`）が、面の中心どうしの線分が他のどのノードの外形（余白 2 単位）とも、グループの題とも交わらない辺だけ `route: straight` にした IR に置き換える。決めた線は直交ルーターで実際に試してから採る（`fits`）。順番は (1) 面の中心どうしの直線（他のノード・題と交わらず、直線ルートの検査も通る）、(2) 迂回: 横に並ぶ端は上面どうし（見える）か下面どうし（隠れる）、縦に並ぶ端は右の側面どうし（東、見える）か左の面どうし（西、隠れる）で、間のノードを越える持ち上げ量の合計が小さい側から（同じなら上・右）、(3) どれも通らなければ `centerPorts`（従来の `ports: center` の端で通常のルーティング）。書いていない経路について診断は出さない。迂回は、上を通るなら両端の上面の中心から真上に出て、間のノードの上を水平に渡り、相手の上面の中心へ真下に入る（矢じりは上面の上）。下・左は隠れた面の中心を狙い、シルエットで止める。IR の `faceSides`（`north` / `south` / `east` / `west`）が端の側と位置（面の中心）を指定し、ルーターが ∏ 形の 3 本の線を描く。
  - **`ports: center` は従来どおり**（立体の 3D の中心を狙い、隣どうしはルーターで重なりの中央へ矯正）。出力は #580 のときと同じ。
  - **従来の `ports: face`（オプトイン、#582）との関係**: 同じ名前を既定にして置き換える。違いは 2 点: (1) 隣どうしでスライドして直交の 1 本にそろえるのをやめ、面の中心どうしの直線にした、(2) 左・底の隠れた面も面の中心を狙う。ルーターに残る面の端（書いたアンカーが相手側だけ、`fanIn` を書いた図）は従来の面の中心の端のまま（スライドの処理は、整列される単独の端のために残る）。
- **採らなかった案**:
  - 面の中心に向けて直交ルーターで折る（中心どうしが同じ高さでなければ折れ線になり、要望の「面の中心どうしを結ぶ」に合わない）。
  - 中心どうしの線を水平にスライドする（利用者が「スライドしない」と明示した）。高さの違う立体を `align: end` で並べると線は斜めになる。水平にしたければ `align: center`。
  - 常に直線にする: 間のノードを貫く（初版）。レビューで、スキップ接続の退行になるため、線がほかのノードを通らないときだけ直線にする条件に変えた。
- **互換性**: cuboid を使わない図の出力は変わらない（`gallery:check`、example のハッシュは変わらない）。変わるのは cuboid を使う図だけ: `sumi/cuboid` のギャラリー（8 テーマの SVG、`sumi-cuboid.md`、`docs/gallery/README.md` と `index.html` の説明文）、`cnn-volumes` のベースレイアウト（YAML、SVG、PNG、`previews.json`）、`sumi/cuboid` の PDF corpus・picture PPTX・編集可能 PPTX の golden。`cnn-volumes` は `align: end` から `align: center` に変えた（隣どうしの線を水平にするため）。`geometry/low-stroke-contrast` は cuboid の面の陰影色を背景として見る。
- **既知の制限**: 間にノードがある線は上（または下）を回る 3 本の線で、他のノードの背が高いと持ち上げが大きくなる。面の中心どうしなので、高さの違う立体を `align: end` で並べると線が傾く。同じ 2 ノードを結ぶ 2 本目の線（往復）と、`fanIn` を書いた図は直交ルーター。
