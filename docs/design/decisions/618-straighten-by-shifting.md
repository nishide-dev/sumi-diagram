# #618 ノードを余裕の範囲でずらして、つながった端を揃える（`figure.layout.straighten`）

## 背景

#603 のドッグフーディングで、向かい合う 2 つの箱の端が少しずれているために、S 字や階段になるエッジが残った（3-deep-crl の Encoder φ → Critic、6-deepseek-v4 の Router → routed experts、8-kimi-k2 の Tasks → Agent など）。#604 の配線だけの直し（PR #617）はノードを固定したまま線で帳尻を合わせるので、迂回や角の丸みの消失、枝の揃い（llama4-moe）の崩れが残った。利用者の指摘: 人が図を作るときは、線の出る側か入る側のまとまりを少し動かして線を真っ直ぐにする（入口を動かすのは選択肢の 1 つ）。

## 決定

- **任意の設定 `figure.layout.straighten: true`**（structured のみ、auto では `layout/structured-only`）。省略・`false` は従来どおりで、出力はバイト単位で変わらない。名前は動詞で「線をまっすぐにする」ことを表し、エッジのアンカー値 `straight`（端の位置の指定）や `figure.layout.align`（要素を一線に並べる制約）と区別できる。グループごとの上書きは今回入れない（必要になれば同じ名前で足せる）。
- **どこで動かすか**: 構造化エンジンの配置（`figure.layout.align` の解の後）と配線の間（`src/layout/structured/straighten.ts`）。エンジンの 1 回の配置に「ずらし（shift）」を渡せるようにした。ずらしは arrange の item（ノード、グループ、入れ子の stack / row）を、大きさが決まった後の最終配置でだけ平行移動する。大きさの計測には使わないので、箱・グループ・図は決して大きくならない。中身（グループの子孫、入れ子の箱、付属ノード `attach`）はそのままついて動く。
- **対象のエッジ**: 直交経路のエッジ（`route: straight` / `curve`、zoom、自己ループは除く）で、ルーターが解決した両端が向かい合う辺にあり（相手が前方）、ずれがルーター自身の許容（#169、1pt）を超えるもの。
- **動かす量**: まず両端のポートが一線になる量。動ける範囲が足りないときは、アンカーのない端の辺の内側（角から 3pt）に相手のポートが入る最小の量で、その端を辺に沿って相手の線へ寄せる（`ports.ts` の #169 の直線化を、この設定のときだけ許容より遠くまで働かせる）。アンカーを書いた端はその位置のまま（相手の箱を動かしてそこに合わせる）。
- **どの側を動かすか**: 入る側の端を持つ item を先に、次に出る側。それぞれ端の item 自身から外側の箱・グループへ順に試す。候補は配置して、一線になった辺の数 → 直線の辺の数 → 動いた要素の少なさ → 先の候補、の順に並べ、最初に次の検査を通ったものを採る。辺は文書順に、変化がなくなるまで（最大 4 周、400 配置）。
- **動いてよい条件（揃いを壊さない）**:
  - 箱の `align` が中央のときだけ交差軸に余裕がある。**書いた `center` も既定の中央と同じに扱う**（中央は「端を揃えない」ことで、#603 の 8-kimi-k2 のように習慣で `align: center` と書く図が多い。書いた `center` を固定すると kimi の Tasks → Agent → LLM judge が直らなかった）。`start` / `end` / `stretch` は意図した揃いなので動かさない。`gap: 0` の箱、#545 の交差軸の空きを持つ item も動かさない。
  - `place` の item は、その軸の座標をほかの item と共有していなければ動ける（共有は作者が引いた線: 6-deepseek-v4 の y=10mm の主線）。
  - `figure.layout.align` の要素（その軸）を含む item、tokens / matrix のセル、傾いた平面と chat の中は動かさない。
  - **扇（fan）は丸ごとでなければ動かさない**: アンカーのない端が同じ辺に 2 本以上ある要素、または 2 本以上が出る（入る）junction と、その相手たち。扇のエッジ自体も直線化しない（枝の形を揃えたまま: llama4-moe、TRELLIS.2 の enc → lat-shape / lat-mat）。辺に沿って寄せる処理も、相手が junction か共有ポートなら行わない。
  - 箱の枠の中に収まり、キャンバスとほかの全要素の位置が変わらず、動いた要素はほかの要素に 3pt 未満まで近づかず（元から近いものはそれ以上近づかない）、入っていたグループから出ない。
  - そのエッジが直線になり、直線だったエッジはすべて直線のまま。
- **配線で害がないことを確かめる**: 候補を実際に配線し、そのエッジが屈曲 0、ほかのエッジの屈曲が増えない、経路が失われない、配線後の図が大きくならない、ときだけ採る（最大 40 回の配線）。幾何だけの検査では、6-deepseek-v4 で experts → ⊕（`east` → `north`）の縦の区間が 0.9mm になって 3 屈曲になる、group-caption で見出しの下に回り込んで図が広がる、を防げなかった。

## 結果

#603 の 10 図（`research/603-dogfood-v0.19/routes/measure.ts` と同じ物差し、YAML に `straighten: true` を足したもの）:

| 図 | 避けられる屈曲 | 超過屈曲 | 屈曲合計 | hugging | 端スタブ |
| --- | --- | --- | --- | --- | --- |
| 3-deep-crl | 1 → 0 | 2 → 0 | 6 → 3 | 0 | 1 → 0 |
| 8-kimi-k2 | 4 → 1 | 5 → 2 | 10 → 4 | 4 → 2 | 8 → 4 |
| ほか 8 図 | 変化なし | 変化なし | 変化なし | 変化なし | 変化なし |
| 合計 | 10 → 6 | 13 → 8 | 55 → 46 | 10 → 8 | 30 → 25 |

- 3-deep-crl: Encoder φ が 6.5mm 下がって Critic の `east:0.2` に一直線、h_i が 2.5mm 左へ寄って分岐点に一直線。
- 8-kimi-k2: Rollouts グループと Filtering グループが下がり Tasks → Agent → LLM judge が一直線、Policy after SFT が上がって Inference に一直線。
- 6-deepseek-v4 の Router → experts は**直らない**。experts を 4.3mm 下げると Router の右辺に入り直線になるが、experts → ⊕ の書いたアンカー（`east` → `north`）の縦の区間が 0.9mm になり 1 → 3 屈曲になる。屈曲の合計は 21 → 19 に減るが、ほかのエッジを悪くしない規則で採らない。Router は y=10mm を u / ⊕ / h と共有する主線で動かない。experts → ⊕ のアンカーを外すか、⊕ の位置を変えれば直る。
- 1-nsa・2-gated-attention・10-multi-agent-research の残りはアンカーで決まる扇や、行の主軸方向のずれ（交差軸でない）で、ずらしでは直らない。

全例・Skill のレイアウト 33・README の図・レイアウト/幾何/色のテスト図（構造化 70 図）に強制的に有効にした比較: 変化 4 図（屈曲 258 → 250、直線のエッジ 542 → 546、悪化したエッジ 0、警告の増加 0、キャンバスの変化 0）。llama4-moe・hierarchy-tree・embedding-gemma は扇の規則で変わらない。

## 採らなかった案

- **整列を常に柔らかく扱う**（`start` / `end` / `stretch` も動かす）: 表の見出しや左揃えの列など意図した揃いが崩れる。
- **書いた `center` を固い揃いとして扱う**: 安全だが、#603 で最も効いた kimi の 3 本が直らない。
- **主軸方向の空き（strut）で動かす**: 箱が伸び、後続の項目がすべて動く（`figure.layout.align` の仕事）。
- **辺に沿って寄せるだけ**（#604 / PR #617 の方向）: 入口が箱の端に寄り、迂回も残る。利用者の方針どおり、まずノードを動かし、足りない分だけ寄せる。
- **幾何の検査だけで採る**: 上の 2 例のように、移動で別のエッジが悪くなるのを見落とす。
- **既定で有効にする**: 10 図とギャラリーで悪化は 0 だが、図の見た目が変わるので、比較を見て利用者と決める（#618 の作業内容どおり）。

## 互換性

- `straighten` を書かない図、`false` の図の配置・D2・SVG・PDF・PPTX はバイト単位で変わらない（`bun run gallery:check` 491 ファイル一致、ピン留めの再現ハッシュ不変、テストで off と省略の LayoutIR が一致）。エンジンの変更（ずらしと配置位置の記録、chat の配置の関数への切り出し）は、ずらしが空なら従来と同じ計算。
- JSON Schema に `figure.layout.straighten`（boolean）が増える。新しい診断はない。

## 限界

- グリッドのセル、chat、傾いた平面の中は動かさない。動かせないときに「どちらを動かせば揃うか」を示す lint のヒントは #604 の `geometry/avoidable-bend` 側の仕事として残す。
- 配置の候補ごとにルーターで端を解決し、採る前に配線するので、有効にした図の配置は遅くなる（70 図で合計約 1.1 秒の追加、最大 400 配置・40 配線で打ち切り）。
- 図の外端にある item が内側へ動くと図が縮むため、その移動は採らない（ほかの全要素が動くことになる）。
