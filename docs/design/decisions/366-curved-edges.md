# #366 一点に集まり広がる曲線経路

## 背景

GCN の Figure 1 のような、複数の入力から hidden junction に集まり、破線の先から再び広がる図では、直角経路は階段状になり、#349 の直線は接続点で接線が揃わない。端点配置と経路の指定を分離し、明示した場合だけ曲線を描く。

## 決定

- structured の edge に `route: curve` を追加する。省略時と `route: straight` は従来通り。auto では位置付き `layout/structured-only`。直角ルーターを先に実行した後、最終座標から独立した単一の三次 Bézier を作る。障害物回避・共有幹・fanIn・交差回避・junction の角丸には参加させない。
- 端点の決定・セル参照・輪郭への投影・固定接点の優先は #349 と共通。junction は中心に接続する。通常ノードの自動接線は端点間の弦方向とする。形状中心から輪郭へ投影した線に沿うので自然に外へ出る。明示した side/offset アンカーと固定接点では side の外向き法線を使い、終点はその逆向きに入る。`straight` アンカーは自動端点・自動接線と同じ。
- junction の基準接線は、through 辺自身を含む全接続辺から junction ごとに一度だけ決め、全 incident curve に適用する。別 junction へ繋がる辺、次に非 curve 辺を参照し、候補が複数なら安定した edge key 順で決める。既に経路がある辺は junction に接する最初／最後の区間、まだない辺は中心間の方向を使う。どちらもなければ、全接続辺の中心間変位の絶対値を各軸で合計し、大きい軸（同点は水平）を共通方向にする。各曲線への適用時は弦との内積が負なら符号を反転し、進行方向へ揃える。明示 side アンカーは各端点でこの基準接線を上書きする。GCN の水平破線なら全曲線が水平接線になり、斜めの curved through 辺も両端の branch と同一直線方向の接線を持つ。当該辺を候補から除く案は through 辺だけ異なる支配軸へフォールバックするため採らない。
- 両ハンドルの長さは端点間距離の 1/3。方向だけを接線に合わせる。新しい曲率パラメーターは増やさず、単一の決定的な形とする。Layout IR の `points` はこの場合だけ始点・制御点2個・終点の4個を保持する。
- 自己ループ・端点箱の重なり・輪郭と交わらない端点・固定接点の裏側からの接近・矢印を収められない短い経路・zoom との併用は #349 と同じ `layout/no-route`。弦が端点内部を通るかの検査は `route: straight` だけに適用する。curve は cubic を構成してから標本化し、実際の出発・到着区間や途中の区間が自分の端点の描画境界へ進入／再進入する場合に同じ error にする。円・菱形の offset アンカーで弦が端点内部を通っても、曲線自体が外側を通る有効なアーチは許容する。弦だけの拒否は曲線の衝突を示さないため採らない。無理な曲線を直角経路に置き換えない。
- SVG の wire と inspection 用 connection はともに本物の `C` 命令。tone・variant・線幅・破線は既存の edge style を使う。矢印の向きは制御点から求めた厳密な端接線。wire は矢印の下で切り詰め、弧長の標本化で切断パラメーターを求めた後、De Casteljau 分割で正確な部分曲線を描く。
- ラベルは #349 と同じ水平文字・局所接線の左側・1.5pt の法線余白。既定は弧長中点。`labelAt: start | middle | end`、`labelSide: left | right` を受け付ける。端寄せは文字の半対角長と矢印長を余裕として取り、短ければ中点に制限する。文字と制御点の包絡を content/canvas に含める。制御点の包絡を使うのは、極値計算より保守的で単純な canvas 保証を得るため。
- geometry lint は曲線を標本化して `geometry/edge-through-node` / `geometry/edge-crosses-label` 等の既存ルールへ渡し、YAML の位置と関連要素の位置を報告する。標本数は制御多角形長1単位につき1（最少32・最大4096）。既存の非 curve の flatten 処理は変更しない。矢印の直線幹長を検査する `arrowhead-on-bend` / `arrowhead-cramped` は滑らかな curve には適用しない（微小な標本区間を「曲がり角」と誤認するため）。
- PDF と画像 PPTX は同じ SVG を変換。編集可能 freeform PPTX は既存の `cubicBezTo` 変換で曲線・矢印を保持する。glued は直線コネクタへの置換で滑らかさを失うため、curve を含めると既存の `pptx/unsupported-geometry` で freeform を案内する。黙って形を変えない。

## 互換性と検証

既存図の route 未指定／straight は同じ経路を通す。禁止された調査領域と指定除外名を除き、変更前後の全 YAML を固有テーマと全組み込みテーマで描画し、SVG / PDF / 画像 PPTX / 編集可能 PPTX（freeform・glued）/ D2 の sha256 と失敗診断を比較する。件数と結果は PR 本文に記録する。既存 golden の変更は意図しない。

回帰テストは4本の色付き入力と4本の出力、水平・垂直の junction 接線、全テーマ、円・菱形の輪郭、明示アンカー、両端矢印、ラベルの左右と端寄せ、位置付き重なり診断、弦と異なる曲線の標本化、各 export と glued の明示拒否を検査する。追加 fixture と Skill の短い例は CLI で PDF に変換し、`pdftoppm -png` で目視確認する。

PR #376 のレビュー修正では、60pt gap の2列 `[a, j1]` / `[j2, b]` を全て curve で繋ぎ、両 junction の接線の共線性と辺順の独立性を検査する。円・菱形それぞれの `north:0.1` 同士のアーチでは輪郭接続・上向きハンドル・lint を検査し、同じアンカーの straight は引き続き拒否する。追加3テストはレビュー修正前のモジュールでは全て失敗する。検証時も `research/` と指定除外名を開かず、チェックの対象設定とテスト選択に除外を適用する。再実行の件数と互換比較結果は PR 本文に記録する。

レビュー修正後の互換比較では、機能追加前 `763607b` の tracked YAML から除外対象を除いた既存103図 × 6テーマ条件（618入力）を使用した。411成功入力の SVG / PDF / 画像 PPTX / 編集可能 PPTX 両方式 / 生成 D2 と各形式の診断、207失敗入力の診断は全て一致した。baseline の対象モジュールは Git からメモリへ読み込み、D2 は stdin/stdout で描画した。例外・入力の追加欠落・既存 golden の変更はない。

レビュー修正後のチェックは、除外用一時設定での Biome（384ファイル）・型検査、Schema freshness、gallery（237ファイル）、icons、shard 検査が成功した。`CI=1 bun run test` は禁止された fixture を参照する20 suite を除いた139ファイルで4,210成功・失敗0件。曲線テスト単独も12成功・失敗0件。除外対象を含む通常設定の無制限な全体実行は行わない。
