# #657 書いたアンカーに向かう辺へ Z で入る（3 回曲がる横入りを避ける）

## 背景

#647 で #639 run 9 の図を縮める途中で見つけた。`place` で置いた working → completed（`fromAnchor: "south:0.25"`、completed 側はアンカーなし）が、completed の東の辺に 3 回曲がって入った。completed の既定の辺は、中心どうしの向き（`facingSide`）で横の差が縦の差より大きいので東になる。東の辺へは working の真下にある failed が邪魔で L 字（1 回）が引けず、failed の上を横に走って 3 回曲がる。北の辺に入る Z（2 回）は障害物なしで引けた。`geometry/avoidable-bend`（#604）は、向かい合う辺どうしの階段か書いたアンカーのずれしか見ないので、何も言わなかった。

## 決定

- **ルーターが向かいの辺への Z を試す**（`src/layout/route/facing-z.ts` の `withFacingZ`）。`routeEdges` で直線・曲線・zoom のエッジまで加えた後に判定するので、それらの端とエラーも数える。対象は次をすべて満たすエッジ:
  - 曲がりが 3 回以上の直交経路（lane、`route: straight` / `curve`、zoom、自己ループ、立方体の面の経路は除く）
  - 一方の端だけにアンカーを書いてあり（辺 S。`straight` は対象外）、もう一方の端にはアンカーがない
  - アンカーのない端がノード（ジャンクションや固定ポートのレンダラーではない）で、書いた辺 S の先にあり、今は S に向かう辺（S の反対の辺）以外に入っている
  - その端の点も、S に向かう辺も、ほかのエッジの端が使っていない（扇・多重辺・ほかのポートの形を崩さない）。直線・曲線のエッジは端の点に最も近い辺を使っているとみなす。zoom のエッジはノード全体を使うので、zoom のエッジが付いたノードの端は動かさない
- 対象のエッジごとに、アンカーのない端を S に向かう辺に置いて（`EdgeLayout.facingEnd`。アンカーと違い、辺の上の位置は従来の既定の決め方: 多重辺の分け方、#113 の分離、#169 の直線化に従う）**図全体を配線し直し**、そのエッジの曲がりが 2 回以下、ほかのどのエッジの曲がりも増えない、配線のエラーが増えない、ときだけ採る（そのエッジの曲がりは必ず減る）。**候補は試すたびに、その時点の配線から探し直す**。採った移動で、ほかの候補がすでに 2 回以下になる、向かいの辺がふさがる、端の点が共有される、ということがあるため。試すのは文書順に **4 回まで**（`FACING_Z_BUDGET`）。試しの配線ではヒントの試し（`hintTrials`）を省き、端が動いたときだけ、求められた設定で最後にもう 1 度配線する。
- **書いたアンカーは変えない**。動かすのはアンカーのない端の辺だけ。L 字（1 回）で既定の辺に入れる図は対象にならない（3 回以上のときだけ試す）。
- `facingEnd` は Layout IR のエッジに残る。描画・lint の確認・`straighten` の試しは同じ `routeEdges` を通るので、どこでも同じ選択になる。
- **`geometry/avoidable-bend` に 4 つ目の場合を足す**: 上の条件のエッジで、アンカーの位置から S に向かう辺の中央へ 2 回曲げの Z が、ほかのノード・見出しのクリアランスを保って引ける（#604 の `twoBendFits`）とき、ルーターが残したものとして報告する。ヒントは書くアンカー（例 `toAnchor "north"`）。#604 と同じく図の写しに書いて配線し直し（`verified`、1 図 8 回まで）、そのエッジが 2 回以下になり、ほかが悪くならなければ「確かめた」と書く。確かめられないとき（2 回より多く曲がったまま、ほかのエッジが増える、配線のエラー、確認の回数切れ）も報告はし、確かめていないことと、今の辺に入る余地を作る別の直し方を書く。

## 採らなかった案

- **既定の辺の決め方（`facingSide`）を変える**（書いたアンカーの反対の辺を常に選ぶなど）: 何もないときの L 字（1 回）まで Z（2 回）に変わる。障害物で決まることなので、配線して比べる。
- **探索の中でアンカーのない端の辺を自由にする**: ポートの分け方・扇・#113 の分離・直線化が辺を前提にしていて、影響が広い。
- **両端ともアンカーのないエッジも対象にする**: 既定の辺どうしの迂回は今回の報告の範囲外で、出力の変化が大きくなる。必要になれば同じ仕組みで広げられる。
- **lint だけで知らせる**: 書き手が毎回アンカーを書くことになる。ほかを悪くしない Z はルーターが引けばよい。

## 互換性

- ギャラリーと examples（`bun run gallery:check` 494 ファイル）は main とバイト一致。ピン留めした再現のハッシュも変わらない。
- 出力が変わるのは、上の条件に当たる図だけ（#657 の縮小図では、高さが 56.09mm → 49.92mm になり、success のラベルが線の脇に来る）。
- 配線の時間: 対象のエッジがある図だけ、1 回の配線につき最大 4 回（採ったときはさらに 1 回）の配線し直しが増える（`straighten` の試しの配線ごとにも同じ）。対象のない図は候補を探すだけ。
