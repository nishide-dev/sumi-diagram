# #545 集合の大きさ、幅の統一、整列を回避策なしで書く

- **背景**: #538 の再計測と #539 のレイアウト作成で、整列と大きさを決めるのに回避策が要った。5 項目を最小の再現にして、機能・診断・文書に分けた（#517 と同じ進め方）。
- **決定（項目別）**:
  1. **集合の大きさを正確に指定できない**: **機能**。集合に任意の `width` / `height`（`minWidth` と同じ `SizeLength`、0.5pt の倍数、正）を追加した。外形はフィットの中心を保ったまま、その大きさになる（`circle` / `ellipse` / `rect`。傾けた楕円は自身の軸に沿う。`hull` は `ref/set-min-size-needs-fixed-shape`）。片方の軸だけ書けば、もう一方はフィットのまま。メンバーが（`padding` を含めて）その大きさに入らないときは、外形を切らずフィットの大きさのまま残し、`layout/set-size-too-small`（warning、集合と軸と両方の大きさを示す）を出す。メンバーの入る判定は楕円・矩形の内側に `padding` を引いた領域に全点が入るかで行う。同じ軸の `minWidth` / `minHeight` と一緒に書くと `ref/set-size-conflict`（error）。再現: `set-taxonomy` は `minWidth: 58mm` で「そろえた」つもりだったが、fam-b / fam-c のフィットが 60.8mm で、実際は 4 つの幅が揃っていなかった（exact にすると警告が出て分かる）。
  2. **同じ種類の箱の幅をそろえる**: **機能**。ノードに任意の `matchWidth: <name>` を追加した。同じ名前のノードは、置かれた木によらず、最も幅の広い本体の幅になる（`props.width` は比較の幅に数える）。箱だけが対象で、固定縦横比の形（円・正方形）と outline コンポーネントは大きさを変えない。auto エンジンでは `layout/structured-only`。レイアウト側のリスト（`figure.layout.equalWidth: [[ids]]`）は、IDの検査と診断が増えるうえ、ノードを足すたびに 2 か所を直すことになるので採らなかった。grid の `align: stretch` は列に合わせて広げる別の手段として文書に残した。
  3. **grid の複数列にまたがるグループの中身を上の列にそろえる**: **文書**（機能は足さない）。グループの木はグループ自身で測られ、padding の分だけ中身が列から内側にずれる。中身の箱を `列幅 - 2p`、箱の間を `columnGap + 2p`（`p` はグループの padding、`props.padding` で明示すると計算が簡単）にすると、グループの自然な幅がちょうど 2 列になり、各箱の中心が上の列の中心に来る。`structured.md` に式と数値例を書き、テスト（`exact-sizes.test.ts`）で式を固定した。グリッドのトラックをグループの木に貸す機能は、グループを 1 つの item として測る現在の契約（サイズ→トラック→配置の順）と循環するので見送った。
  4. **stack の中の要素に `align` を効かせるには 1 要素の `row` で包む**: **機能**（既定の探索は変えない）。`align` の探索を 2 段にした。まず従来どおり主軸の空きだけで解き、満たせない制約があって、制約の要素がちょうど他種の箱（`x` なら stack、`y` なら row）の直接の item のときだけ、その箱の交差軸の空き（stack の item の左右、row の item の上下）を足してもう一度解く。残りの距離が小さくなるときだけその結果を採る。従来の探索で満たせた図は同じ配置（examples とピン留めの再現は不変）。対象は要素を直接持つ箱だけで、枝全体は動かさない。grid のセル、1 行の `tokens` のセルと matrix は対象外（#306・#305 の契約を保つ）。`layout/unsatisfied-align` の hint の文言は変えていない。
  5. **複数列にまたがる箱から、まっすぐ降ろすのに端数のアンカーが要る**: **機能**（`straight` の規則は変えない）。アンカー値 `straight:span` を追加した（`straight` と同じに解析し、エッジの IR に `straightSpan` を記録する）。相手の中心が辺の真上にないが 2 つの箱が重なるとき、重なった区間の中央に、両端の辺の角から 3pt 内側という条件で端点を置く。両端に書く。`straight` を直接拡張すると、#306 の span の hint（広い箱の幅・stretch の案内）と `layout/straight-off-side` の既存の契約が変わるので、別の綴りにした。`layout/straight-off-side` の hint は、重なる区間があるときに `straight:span` を案内する（従来の端数のアンカーの数値も残す）。
- **レイアウトの扱い**: `timeline-lanes` の端数のアンカー（`south:0.7692` / `north:0.2308`）を `straight:span` に置き換えた。描画は 0.011 unit ずれるだけで見た目は同じ（PNG は再ラスタライズのみで差し替えない）。`set-taxonomy` は `minWidth` のまま: exact の 58mm はメンバーに足りず（fam-b / fam-c は 60.8mm）、61mm にすると図が 180.45mm で幅の上限を超えるため、見た目を保てない。
- **採らなかった案**: `straight` に重なり区間の中央を自動で採らせる（#517 で採らなかった理由に加え、#306 のテストと hint が変わる）。集合の大きさを `minWidth` の延長として「縮める」（メンバーを切る）。交差軸の空きを常に使う（grid のセルと tokens のブロックの契約が変わり、`examples/clip` の配置が動いた）。
- **互換性**: 追加はすべて任意の項目・綴りで、既存の図の出力は変わらない（gallery・examples・ピン留めの再現ハッシュは不変、JSON Schema は `width` / `height` / `matchWidth` / `straight:span` が増えるだけ）。新しい診断は warning 1（`layout/set-size-too-small`、`width` / `height` を書いた集合のみ）と error 1（`ref/set-size-conflict`）。以前は `layout/unsatisfied-align` だった「stack の item を `x` で、row の item を `y` で動かす」図は、警告が出ずに整列する。
