# #491 waveform の波形色とラベル配置

## 背景

- emphasis の塗りと信号の色が同じで、信号が見えなかった。
- ラベル付き waveform は枠内の下部（高さの 70〜90%）にラベルを置き、信号を 10〜60% の帯へ押し上げていた。自動サイズでは枠の高さをラベル高さの 5 倍（`h / 0.2`）にしたため、ギャラリーのラベル付き waveform は約 152pt の縦長の枠になっていた。

## 決定

### 信号の色

emphasis の信号は、塗りに合わせた variant の文字色で描く。IR が `render.params.signalStroke` に解決済みの文字色を入れ、SVG（auto の合成・structured の描画）はこれを使う。枠の線色（`frameStroke`）とは独立。下記のキャプション色の補正は信号に影響しない。全組み込みテーマ × 全 variant で、信号と塗りのコントラストが 3 以上であることをテストする。

### ラベルは枠の外、下の中央

- `label` は枠の外、枠の下の中央に置くキャプションとする。キャプションの行ボックスの上端は、枠の下端から `captionGap()` = キャプションの文字サイズの 0.3 em を 0.5pt 格子（1 unit）に丸めた距離だけ下（8pt の文字で 2.5pt）。文字はさらに行ボックスの half-leading とフォントの ascent の分だけ下になる。当初は `label` ノードを gap 0 で south に attach したときと同じ間隔（行ボックスが枠に接する）としたが、slides などで文字が枠の線にほぼ触れて窮屈だったため、文字サイズに比例する間隔を足した。
- IR の `NodeIR.labelBelow`（`true`）で表す。条件は waveform で、ラベルが空白以外を含み、icon がないこと。icon は従来どおり枠内に描く。
- 描画器は `labelless: true` とした。footprint はラベルに依存せず、自動サイズの枠は両エンジンで 80×48pt（160×96 units）。`hasLabel` パラメータは廃止し、信号は常に枠の上下中央。`safeArea` は枠の内側（左右 10%・上下 10% の内側）で、icon にだけ使う。`props.width` / `height` は枠だけの大きさ。
- **structured**: キャプションをバッジ・グリフと同じ「本体からはみ出す装飾」として扱う。葉の大きさにキャプションを含め、整列（row の中央揃えなど）と attach の基準は本体（枠）のまま。ルーターはキャプションの箱をグループタイトルと同じく通れない領域とし、既定の辺が south になる辺はキャプションを避けて横の辺から出る（side input と同じ規則）。`fromAnchor` / `toAnchor` で south を明示すればそれに従い、キャプションを横切れば `geometry/edge-crosses-label` が出る。
- **auto (D2)**: D2 に `label.near: outside-bottom-center` を書く。ELK はキャプションの分の場所を節点の下に確保し、辺は枠に付く。合成でキャプションを structured と同じ位置（枠の下端 + half-leading）へ動かす。
- **キャプションの色**: キャプションは塗りではなくキャンバスの上に描かれる。文字色が塗りのための色（キャンバスより塗りとのコントラストが高い）で、キャンバスとのコントラストが 4.5 未満なら、その figure のテーマの `label` の文字色に替える（sumi・sumi-dark・llama の emphasis）。太字などほかの文字の設定は保つ。全組み込みテーマ × 全 variant でキャプションとキャンバスのコントラストが 3 以上であることをテストする。
- **幾何 lint**: キャプションは枠の中にないので、`labelArea` と `labelBoundaries` を持たない。`geometry/label-overflow` は代わりにキャプションが枠に重ならず、枠の下端から `captionGap()` 以上離れていることを検査する。衝突・キャンバス外・辺との交差はキャプションの実際の位置で従来の規則が検査する。`geometry/edge-touches-label` はキャプションも自由なテキストとして扱う。
- **編集可能 PPTX**: キャプションを枠の text body ではなく、別のテキストボックス（`<key> label`）として枠のグループの後に書く。glue の接続先は枠のまま。PDF・画像 PPTX は SVG から作るので変更不要。

## 採らなかった案

- **内側の配置を prop（`labelAt: inside | below`）で残す**: 内側の配置を使うコミット済みの図がない（EmbeddingGemma の waveform 自体はラベルを持たず、別の `label` ノードを南に attach している。ギャラリーの見本は生成物）ため、残さない。
- **キャプションを描画器の `safeArea` として枠の外に置く**: `safeArea` は描画の内側にあるという契約で、lint・ポート・サイズ計算がそれに依存する。描画器はラベルの大きさを知らないので、枠と外のキャプションの分割をパラメータで渡す必要もあった。ノード側の性質（`labelBelow`）として、レイアウトと lint で扱うほうが単純。
- **キャプションを別の `label` ノードへ展開する**（グループの caption #130 と同じ）: ノードの label でなくなり、検査・PPTX・Skill が二つの要素を扱うことになる。
- **auto でキャプションの場所を D2 に知らせない**: 下の要素と重なる。

## 互換性・確かめたこと

- 変わる出力: ラベル付き waveform（ギャラリーの `sumi/waveform` の見本 8 テーマ）。枠が約 152pt の縦長から 48pt になり、ラベルは枠の下に出る。emphasis のキャプションの色は上記のとおり。
- auto で ELK はキャプションを含む箱の中央で揃えるため、横並びの隣の要素と枠の中心が数 pt ずれ、辺は枠の中心より下に付く。D2 の外側ラベル一般と同じ振る舞いとして受け入れる。structured は枠の中心で揃う。
- 集合（sets, #407）の囲みは waveform の枠に合わせ、キャプションは含めない（未対応。必要になれば別 issue）。
- `examples/` の全 PDF を `origin/main` と 150dpi で比較し、差分は全図で 0 画素（EmbeddingGemma の waveform はラベルなし・明示サイズのため不変）。
- 回帰テスト: 両エンジンでキャプションが枠の下の中央、枠の下端 + 0.3 em + half-leading の位置にあり幾何 lint が空、辺の端点が枠にありキャプションより上、自動サイズの枠が 160×96 units、編集可能 PPTX のキャプションが枠の下の別テキストボックス、全テーマ × variant のキャプション・信号のコントラスト。
