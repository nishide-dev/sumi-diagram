# #435 基準の図と並べて見た目を批評する段階（`scripts/compare`）

## 背景

密度の lint（#422）や配色の lint（#423）は、面積の比率や色の距離しか見られず、良い図と悪い図を僅差でしか分けられなかった。論文図の弱さは、疎さ・要素の大きさの不揃い・空白の穴・主役の不在・配色の不統一・文字の多さ・段階の流れの乱れとして現れる。TriCL（#420）と LLaDA（#421）の再現では、描いた図を基準の図と同じ幅で並べて画像で見比べると、これらを確実に拾えた。

## 決定

- Skill に `scripts/compare` を足す。`compare [-o out.png] [-w 幅] [--side] <図.svg|pdf|png> <基準.png>...` で、1 枚目（自分の図）と基準の PNG を同じ幅にそろえ、ファイル名のラベル付きで縦に積む（`--side` で横に並べる）。出力は図の隣の `<図>-compare.png`。
- SVG は同じ場所の `preview` で PNG にし、PDF は `pdftoppm`、なければ macOS の `sips` で PNG にする。合成には ImageMagick（`magick`、なければ `convert`）を使う。
- ImageMagick がないときは、合成せず exit 1 で、見るべき画像の一覧を示す（無理に別の方法で合成しない）。ラベル用のフォントが見つからないときは、ラベルなしの灰色の帯で作り、画像の順を標準エラーに出す。
- 終了コードと後始末は `preview` に合わせる（使い方の誤りは 2、道具がない・失敗は 1、失敗時は一時ファイルも出力も残さない）。
- SKILL.md の手順 7 の 4 に「基準の図と並べた批評」を必須として置く。近い基準 1〜2 枚（密な概観図なら TriCL か LLaDA を含める）と並べ、固定の観点で批評し、直して繰り返す。可能なら描いた本人とは別の視点（画像と観点だけを渡したサブエージェント）で行う。観点の詳細は `references/layout-tips.md` の「Critique against references」に置き、SKILL.md は 250 行未満のままにする。
- 密度・配色の lint の info は、この批評の入力であって最終判断ではない、と明記する。

## 採らなかった案

- `preview` の拡張: PNG 化と合成は入力も出力も別で、`preview` の使い方（SVG 1 枚、サイズ）が複雑になる。別スクリプトにして、SVG の PNG 化だけ `preview` を呼ぶ。
- ImageMagick なしの合成（`sips` と手作業の積み重ね）: `sips` は画像を合成できない。偽の成功より、明示的な失敗と代替の見方を選んだ。
- lint だけで判定: #422 の結果のとおり、見た目の判断は面積比では足りない。

## 互換性

Skill のスクリプトと文書だけの変更。コンパイラ・レンダラ・テーマ・部品は変えておらず、すべての図の SVG/PDF/PPTX/D2 は変わらない（`bun run gallery:check` とゴールデンのテストで確認）。
