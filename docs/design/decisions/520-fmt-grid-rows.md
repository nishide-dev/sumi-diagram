# #520 fmt は grid の items を 1 行 1 row で出力し、flow の括弧に空白を入れない

- **背景**: `sumi fmt` が、手で row ごとに改行した grid の `items` を 1 行にまとめ、`[a, b]` を `[ a, b ]` に書き換えていた。#509 では、行の構造が消えて後続の sed や手編集が黙って外れた。
- **決定**:
  - flow 形式の `items` を持つ block 形式の `grid` で、row が 2 行以上になるとき、`columns` セルごとに改行する（`span` を数え、null セル `~` とマッピングのセル、入れ子の grid もそのまま 1 セルと数える）。出力は `items:` の次の行に `[` を置き、2 行目以降は `[` の分だけ字下げする。row が 1 つだけなら 1 行のまま。
  - flow コレクションの括弧の内側に空白を入れない（`{a: 1}`、`[a, b]`）。カンマの後は空白 1 つ。以前は `{ a: 1 }` / `[ a, b ]` だった。
  - コメントを含む `items`、block 形式の `items`、flow マッピングで書かれた grid は従来の規則のまま（コメントを保てないため）。
  - 再整形しても同じ出力になり（安全検査が検証）、データは変わらない。
- **採らなかった案**: 括弧の空白を保つ（yaml ライブラリはコレクションごとの保持ができず、元の書き方に依存させられない）。マッピングだけ空白あり・配列だけなしにする（規則が複雑になる）。block 形式の `items` を並べ替える（作者の選んだ形式を変えない原則に反する）。
- **互換性**: fmt の出力が変わるため、`examples/`、`skills/sumi/examples`、`docs/assets/architecture.sumi.yaml` を整形し直した。描画結果は変わらず、SVG メタデータの `input-sha256`（ソースのバイト列の hash）だけが変わる。
