# #430 集合の傾いた楕円（`angle`）

## 背景

TriCL の Figure 1 の再現（#420）で、hyperedge は斜めに並んだメンバーを傾いた楕円で囲む。#407 の
`shape: ellipse` は軸に平行な楕円だけで、斜めの並びを囲むと縦横の外接矩形にそろえて大きくふくらむ
ため、`shape: hull` で代用した。凸包は直線の辺と小さな丸い隅の連なりで、多角形に見えてガタガタに
なった。元の図の楕円はなめらかで、メンバーに沿って傾いている。

## 決定

### スキーマ: 楕円に `angle`

```yaml
sets:
  - { id: e, members: [a, b, c], shape: ellipse, angle: auto, padding: 3mm }   # メンバーの並びに傾ける
  - { id: f, members: [d, g],    shape: ellipse, angle: 30 }                  # 30° で固定（時計回り）
  - { id: h, members: [x, y],    shape: ellipse }                              # 従来の軸平行（変わらない）
```

- `angle`（`-180`〜`180` 度、または `auto`）は任意。単位は度、ページ上で時計回り（SVG の `rotate()` と
  同じ。y が下向き）。傾けた楕円の `rx` の軸が、その向きに延びる。
- **オプトインにした（新しい shape 名は足さない）**。`angle` を書かない `shape: ellipse` は、従来の
  軸平行（縦横比 1:3〜3:1、外接矩形で伸縮した最小包含円）のまま、出力が 1 バイトも変わらない。
  向きは形の種類ではなく楕円の属性なので、shape の語彙を増やさず `angle` で選ぶ。issue の「既定を
  変える場合は相談」に当たるため、既定は変えない。
- `angle: 0` は「軸平行で最もきつく囲む」指定で、`angle` なし（従来の 3:1 制限つき）とは別。
  従来の形を残したい図は `angle` を書かなければよい。
- `circle` / `hull` / `rect` に `angle` を書くのはエラー（`ref/set-angle-needs-ellipse`、`sets[i].angle`
  を指す）。無視すると、向きを指定したつもりの図で気づけないため。エラーのある集合は、ほかの集合の
  エラーと同じく文書から外す。
- 角度は 1/1000 度に丸める（輪郭の他の値と同じ、決定論的）。`auto` は丸めた角度で最後にあてはめ直す。

### あてはめ（`src/layout/ellipse-fit.ts`）

- **padding を先に足す**。メンバーの点（矩形は 4 隅、`circle` / `oval` は境界の 32 点）の凸包の各頂点を、
  半径 padding の円を外接する 32 角形に置き換え、その凸包を作る。楕円がこの点列をすべて含めば、
  どのメンバーも輪郭まで padding 以上離れる。長短の半径に padding を足す従来のやり方は、傾いた細い
  楕円の平たい側で padding より狭くなる（支持関数の不等式で、`(a+p, b+p)` は `a, b` の楕円のオフセット
  を含まない）ため採らない。足す量は円盤を囲む多角形で 0.5% ほど大きい（外接なので内側には入らない）。
- `angle: auto`: 点列の**最小面積の外接楕円**（Khachiyan 1979、双対の重みへの Frank-Wolfe 法。決定論的）。
  収束の誤差のぶんは、全点が入るまで中心から拡大して補う。長い軸を `rx` にして角度を (-90, 90] に畳み、
  ほぼ円なら角度 0 の円にする。PCA の主軸は、点の分布が偏ると面積が最小にならず、囲みがふくらむため
  採らなかった。
- `angle: <度>`: 点列をその角度の座標系に回し、縦横比を黄金分割探索で振って最小面積を求める（比ごとに
  最小包含円を、軸を伸縮した点列で求める）。比の探索範囲は 1:400。
- **3:1 の制限は傾いた楕円にはない**。制限は、軸平行の楕円が「大きな円」にならないための歯止めだった。
  傾いた楕円の目的は、メンバーに沿って**ぴったり**囲むことで、制限すると斜めの並びが再びふくらむ。
  細くなりすぎるのは padding が下限になる（細さの下限は 2 × padding）ことで自然に抑えられる。
- メンバーが 1 点や一直線でも、padding（0 のときは 0.05 unit）で面積を持つ。

### 形・ラベル・lint・描画

- `SetOutline` の ellipse に任意の `angle`（度）を足した。`angle` がなければ従来と同じ値・同じ式。
  外接矩形は傾いた楕円の厳密な範囲（`√(rx²cos²+ry²sin²)`）で、キャンバスが輪郭を含む。
- ラベルの 8 方向: `top` / `bottom` / `left` / `right` は傾いた楕円の外接矩形の辺に中央で、4 隅は
  傾いた楕円の**支持点**（楕円の座標系で `(rx²u, ry²v)` を回して戻す）に置く。輪郭に重ならない。
- 描画は **3 次ベジェの閉じた経路**（`<path class="sumi-set-shape">`、45° ごとの 8 区間。半径との誤差は
  4e-6 以下）。`<ellipse transform="rotate(...)">` にしなかったのは、検査（`inspectSvg()` の形と
  外接矩形）・PDF・PPTX がどれも transform なしの経路を既に読むため。editable PPTX は `a:custGeom`
  で、傾きは経路に含まれ `rot` 属性は要らない（回転した楕円のプリセットだと、外接矩形・ラベル・
  図形の編集が複雑になる）。軸平行の楕円と円は従来どおり `<ellipse>` / `<circle>`。
- lint（`set-contains-non-member`、`set-label-collision`）は、SVG の経路から読んだ多角形を使うため、
  傾いた形のまま判定する。傾いた細い楕円の外接矩形の隅にあるノードは、メンバーでなくても「覆われた」
  とは数えない。ヒントに `angle: auto` を足した。
- エッジラベルの背景（`backgroundAt()`）の内外判定も、傾いた楕円の式にした。

## 採らなかった案

- **`shape: oriented-ellipse` など新しい shape 名**: 向きは楕円の属性で、`angle` の有無で足りる。
  shape が増えると `circle` / `ellipse` / 新名の 3 つの違いを説明する必要が出る。
- **`shape: ellipse` の既定を `auto` にする**: 既存の図の出力が変わる。issue の受け入れ条件
  （指定しない図の出力が変わらない）に反する。
- **PCA の主軸 + 最小の伸縮**: 偏った点列で面積が最小にならない。最小面積の楕円は点の数が少なく安価。
- **長短の半径に padding を足す**: 傾いた細い楕円の側面で padding を下回る（上記）。
- **`<ellipse transform>` と PPTX の `rot`**: 検査・PDF・PPTX・ラベルの当たり判定それぞれに回転の処理が
  要る。経路なら共通の経路を使える。
- **傾いた楕円にも 3:1 の制限**: 斜めの並びを囲むと、また大きくふくらむ。

## 制限

- `angle` は `shape: ellipse` だけ。`hull` を傾いた楕円にすることはできない。
- 傾いた楕円は SVG の `<ellipse>` ではなく経路なので、SVG を直接編集するときは楕円の属性を持たない。
- 面積が最小の楕円は、メンバーが一直線に近いと細長くなる（padding が短軸の下限）。丸く見せたい
  ときは `padding` を大きくするか、`shape: circle` にする。
- Khachiyan 法の収束は有限で、最小面積より 0.05% ほど大きくなりうる（全メンバーを含むことは保証する）。

## 互換性と検証

`angle` を書かない図は、IR・配置・SVG・PDF・PPTX・D2 のいずれも変わらない。既存の `*.sumi.yaml`
（research/ と非公開の図は除く）116 件を、自身の theme と全組み込み theme（計 812 通り）で、変更前後に
SVG / PDF / picture PPTX / editable PPTX / D2 の SHA-256 を比較し、**変わったものは 0**（error の
code も一致）。ギャラリーは `sets`（新しい 2 つの集合を足した）と目次のページだけが変わる。

回帰テスト: あてはめ（ランダムな点列で、どの点も padding 以上離れること、`auto` が他の角度より面積が
大きくないこと、斜めの並びで軸平行の 1/2 未満の面積）、`fitSetOutline`（`angle` なしで従来と同じ値、
円盤は実際の円で padding を測る）、外接矩形・多角形・経路の一致、8 方向のラベル、スキーマと
`ref/set-angle-needs-ellipse`、SVG が経路になること、lint が傾いた形で判定すること、PDF・picture PPTX・
editable PPTX。視覚確認は TriCL の hypergraph の 1 セルを模した図（3〜4 個の重なる破線の集合、
斜めに並んだ小さなメンバー）を PDF にして pdftoppm で見た。
