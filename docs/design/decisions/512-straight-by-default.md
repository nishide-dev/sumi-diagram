# 512: 幅の広い箱の端点を既定でまっすぐにする

## 問題

#509 の採点で矢印の無駄が最多（32 件中 12 件）だった。幅の広い箱から複数の狭い箱へのファンアウト、およびその逆のファンインが、箱の中央を通る 1 本の幹に束ねられ、狭い箱の手前で段差を作る。`fromAnchor/toAnchor: straight` で直せるが、毎回書く必要があり、配置によっては効かない。

## 原因

`resolveEndsWith`（`src/layout/route/ports.ts`）は、アンカーのない端点を、相手との中心線と箱の辺の交点（辺の中央）に置く。幅の広い箱の中央と狭い箱の中心が合わないとき、経路は L 字か Z 字になり、同じ辺を共有する複数の端点は 1 本の幹になる（`fanIn` の既定が merge）。

## 決定

- `figure.layout.fanIn` が書かれていないとき、次の条件を満たす端点を `straight` と同じ扱いにする（`autoStraight`）。
  - 両端ともアンカーがなく、自己ループ・junction ではない
  - 一方が相手より幅（東西に離れているときは高さ）で 4 単位（2pt）より大きい
  - 相手の中心が、その辺の角から 6 単位以上内側にある
  - 端点どうしを結ぶまっすぐな線が、ラベル・見出し・キャプションの箱を横切らない
- `fanIn: merge` / `spread` を書いたときは従来どおり（幹を頼んだ扱い）。
- 狭い側ではなく広い側に `straight` を置く。これは `layout/straight-off-side` の hint が勧める書き方と同じ。

- 自動の `straight` で経路が引けない図（逆向きの 2 本が同じ口に固定されるなど）は、`fanIn: merge` を明示してもう一度引き、誤りが少なければそちらを使う（`fanIn: spread` の既存の再試行と同じ仕組み）。再試行は `fanIn: "merge"` を明示して行う（省略すると自動の `straight` が再び効く）。
- トレードオフ: synthetic grid（100 ノード・146 本）の交差点は 1169 → 1170 と 1 つ増えた。まっすぐに降ろす分、別の線と 1 回交わる場所が増えるため。見た目の改善（段差・迂回の減少）を優先した。

## 結果

- 1-vit-block/A draft1 の patch 5 → 射影層の迂回、4-train-infer/A draft1 の Decoder → 予測トークンの段差が消える。
- DiT・H3-World の `geometry/arrowhead-cramped` / `edge-jog` の既存の指摘が減る（テストの期待値を更新）。
- 例とギャラリーの出力は変わらない（再現図の hash も変わらない）。

## 残り

- 枠に沿う線の lint（`geometry/edge-near-border`）は閾値 1.5pt のまま。枠から 3pt 程度の「近すぎる」線を知らせるかは別途検討する。
- 隣り合う箱の間をまとめて通る幹（7-request-states の cancel）の枠からの間隔は、このPRでは変えていない。
