# #584 cuboid ブロックを端にする普通の線と、縦方向の受容野

- **背景**: #576（PR #583）では、cuboid の部分ブロック（`<node>.<name>`）を指せるのは `zoom` の端だけで、上下に離れたブロックの受容野は 2 本のままだった。この 2 つを扱う。
- **決定**:
  - **普通の線**（`arrow` / `line`）の端にブロックを使える。ブロックを端にする線（zoom 以外）は、IR で `route: straight`（`route: curve` も可）の 1 本の直線として扱う。ルーター（直交ルーティング）はブロックを知らないので、ルーターの外に出し、`addDirectRoutes`（#349）が描く。端の点は、ブロックの 3D の中心（外接形の中央、solid の描画が定める投影上の中心）に向かう線が、ブロック自身のシルエット（`OutlinePart.outline`）に入る点。親 cuboid の `ports: face` は親そのものを端にする辺のためのもので、ブロックには適用しない（ブロックの面の中心に付ける意味づけは、前面以外が隠れる奥のブロックで成り立たないため）。ブロックの接点は、もう一方の端の実際の接点（面のポート・anchor を含む）からブロックの中心への線上に取り、線が必ず中心を通る。もう一方の端が cuboid（`ports: face` 含む）や普通の箱なら、従来どおりの接点規則でこちらを向く。
  - **線が親の中を通ること**: ブロックから出る線は親 cuboid の体積の上を通りうる（辺はノードのあとに描く）。`edge-through-node` は端のノードを障害物にしないので、親は端として扱われ誤検出しない。`straight` の「向きが端に入る」検査は、ブロックの端では親ではなくブロック自身の外形で調べる。`checkRoutes`（端が外形上にあるか）も、ブロックの端はブロックのシルエット上を要求する。
  - **検証**: 未知のブロック名は `ref/unknown-cell`（cuboid には「Unknown block」と、`highlight` の名前の候補を示すヒント）。ブロックの端への `fromAnchor` / `toAnchor` は意味がないので `layout/part-anchor`（旧 `layout/part-needs-direct-route` は廃止）。PDF・編集可能 PPTX は経路の点をそのまま使うので追加の処理は要らない。
  - **縦の受容野**: 両端がブロックで上下に離れている（`zoomSide` が `below` / `above`）とき、横の場合の案 A を縦に拡張して 4 本の線を引く。下にある場合は始点の下面（隠れた面）の四隅 → 終点の上面の四隅、上にある場合は始点の上面 → 終点の下面（隠れた面）。四隅は前左・奥左・奥右・前右の順で対応する（`OutlinePart.faces` に `top` / `bottom` を追加）。隠れた面から出る（へ入る）線は、横の場合と同じ形による処理（`leaves`）で、その体積のシルエットを出る（入る）点から始める（止める）。SVG・PDF・PPTX は同じレイアウトの線を使うので、描画順に依らず同じ見え方になる。
  - **前面のブロックの下面の前の角**: ブロックが体積の前面（z = 0）にあるとき、その下面（隠れた面）の前側の角（面の 0 番と 3 番）は体積の表面に載っているので、線を体積のシルエットで切らず、そのまま下へ描く。奥の角（1 番と 2 番）は体積の中で隠れるので従来どおりシルエットで切る。`OutlinePart.frontPlane` を足した。横向きの左の面は従来どおり全部切る（既存の図・テストが変わらないようにするため）。
- **採らなかった案**:
  - ブロックを直交ルーターの端にする: ルーターは要素の箱と外形を前提にしていて、ブロックのポートと障害物（親を端として通す）の扱いをルーターに足す必要がある。直線にすれば小さく済み、PDF・PPTX・lint の経路が増えない。代わりに他のノードを避けない（`route: straight` と同じ。通れば lint が警告する）。
  - 縦の受容野を外接形の角 2 本のままにする: 横と見え方が揃わず、受容野がピラミッドに見えない。
- **互換性**: checked-in の図・作例・ギャラリー・golden の出力は変わらない（SVG・PDF・PPTX のハッシュが一致）。ただし、上下に離れたブロックどうしの `zoom` を使う既存の入力は、従来の 2 本ではなく 4 本の線になる（意図した変更）。ほかに変わるのは catalog の説明文と、`layout/part-needs-direct-route` の廃止。
- **未実装・今後**: ブロックごとに親と異なる格子。同じ cuboid の 2 つのブロックを結ぶ線（端の箱が重なるため `layout/no-route`）。ブロックを端にする線が他のノードを避けること。
