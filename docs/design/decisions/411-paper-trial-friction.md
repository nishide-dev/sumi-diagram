# #411 論文図の試行で見つかった 5 つの摩擦

v0.15.2 の Sumi と Skill だけで論文の図を描かせた試行（hypergraph の overview 図）で出た不具合を直す。各項目を最小の図で再現してから直した。

## 1. 辺ラベルが枠線や他の線に重なる

### 背景
分岐の辺のラベル（`$+e_r$`）が、グループの下端の枠線の上に置かれた。ラベルは最後の線分が短く（矢じり + ラベル高さが入らない）、候補が「直前の線分の、最後の線分と反対側」の 1 か所だけだったため、その場所が枠線をまたぐと他に選べなかった。

### 決定
`placeEdgeLabel`（`src/layout/route/labels.ts`）の候補に、直前の線分に沿ってずらした場所を、両側に追加した（交差する線・枠線の端のすぐ向こう側を止まり位置にする）。追加分は既存の候補の後ろに並べるので、これまでの候補で枠線・線・ノードのすべてを避けられていた図は選択が変わらない。避けられる場所がないときの報告は、これまでどおり `geometry/label-collision`（枠線・他のラベル）と `geometry/edge-crosses-label`（他の線）が担う。ラベルを置く余白そのものが無い図（試行の図がそう）は、診断が残る。

### 採らなかった案
- ラベルのために hidden junction や stack の `gap` を自動で広げる。junction の位置は幹線の高さに合わせて決まるため、広げても余白が増えない。レイアウトの変更になり、他の図の出力が動く。

## 2. `align: stretch` の `tokens` から出る線の起点

### 背景
`tokens` ノード全体（列全体）は frame グループとして置かれ、`align: stretch` で frame だけが全幅に伸びる。端点の矩形は、注釈（`attach`）があるときだけセルの外接矩形になっていたので、注釈のない stretch では伸びた frame の端（空白）から線が出た。

### 決定
`endpointRects` は、`tokens` の frame を常にセルの外接矩形で扱う（#331 の「辺が指すのは列そのもの」の一般化）。frame を伸ばさない案は、`stretch` の他の部品との一貫性を崩すため採らない。

## 3. 枠線の上を走る横の幹線に `edge-near-border` / `edge-on-border` が出ない

### 背景
2 本の辺が同じ幹線に合流するとき、各辺が描くのは幹線の半分ずつ（それぞれ 3mm 未満）で、検査は辺ごとの断片の長さだけを見ていたため、合わせて 3mm 以上の幹線が枠線の真上にあっても出なかった。縦でも同じ欠陥があった（向きの問題ではない）。

### 決定
枠線の辺ごとに、単独では最小の長さに満たない断片を、同じ線上（0.5 unit 以内）で線幅が同じ、かつ接する・重なるものについて 1 本にまとめてから測る（`joinCollinear`）。単独で 3mm 以上の断片はこれまでどおり単独で測るので、辺ごとの線幅・描かれた範囲で測る既存の契約（§6.39、#163）は変わらない。

## 4. `arrowhead-cramped` の誤検出

### 背景
試行の図で 6 件。そのうち 4 件は矢じりの手前の直線が 1.66pt で、見た目に問題がなかった。ルータは拡大縮小前に 2pt（`ARROWHEAD_STEM_UNITS`）の直線を確保し、`figure.fit: scale`（ここでは 0.83 倍）は矢じりも同じ比率で縮める。判定は印刷後の絶対値 2pt だったので、設計どおりの図が 2pt × 0.83 = 1.66pt で引っかかっていた。

### 決定
閾値を印刷時 1pt（設計の直線の半分）に下げる。縮小率 0.5 以下か、ルータが余白を確保できなかった場合に出る。残った 2 件（直線 0.07pt、矢じりが曲がりの真上）は実際に窮屈で、検出し続ける。重大度は info のまま。

## 5. `scripts/preview` の出力先

### 決定
PNG を SVG の隣（`figure.svg` → `figure.png`）に書く。`-o` / `--out <png>` で別の `.png` を指定できる（出力先のフォルダは作る。`.png` 以外は終了コード 2）。変換は従来どおり一時フォルダで行い、成功時に移すので、失敗時に何も残らない仕様は変わらない。既存の `figure.png` は上書きする。

## 互換性

リポジトリの全 `*.sumi.yaml`（`examples/`、`skills/sumi/examples/`、`tests/fixtures/`）を、各図のテーマと組み込みの 6 テーマで変更の前後に描画し、SVG・D2・PDF・PPTX のハッシュと診断を比べた。出力（SVG/D2/PDF/PPTX）が変わる図はない。変わるのは `fit: scale` を反映する PDF/PPTX 描画の診断（`arrowhead-cramped` の info）だけで、`examples/dit-block`（3 → 0 件）、`b-dit` 系のテスト図（5 → 2 件）、`arrowhead-room-jog`（1 → 0 件）で減り、残る件の文言は「1pt 未満」に変わる。ギャラリー（`docs/gallery/`）はこの診断を載せるため、`bun run gallery` で再生成した。
