# 512: 隣り合う箱の間の幹と、枠からの間隔

#558（`512-frame-trunks-and-side-lanes.md`）の残り。グループ外の箱から、グループ内の箱へ入る線の幹が、グループの枠に沿う例が 2 つ再現した。

## 問題

1. 2-web-system（#509 A）: 同じグループの 2 つの箱（inventory / order）から、次のグループ内の 1 つの箱（postgres）へ入る 2 本の線が 1 本の幹を共有し、その幹が枠の内側 2pt（線と線の間 0.35mm）を走る（`geometry/edge-near-border`）。#558 の余白の拡張は、同じポートから出るファンアウトだけが対象だった。
2. 7-request-states（#509 B の初稿）: 箱の南のポートへ、箱より上から入る線（`toAnchor: south`）は、箱の下で折り返す。折り返しの線がグループの枠の外側 2pt を長く走り、手前では枠を避けて余計な段差も作る。
3. 7-request-states の `cancel`（#538 の `S`、#509 の `A`）: 現在の main では再現しない（枠に沿う線はなく、`geometry/edge-near-border` も出ない）。

`geometry/edge-near-border`（1.5pt 未満、3mm 以上）は 1 と 2 をすでに検出している。しきい値は変えない。

## 決定

`arrowheadPaddingDeficits`（`src/layout/route/padding.ts`）の幹の集計に 2 つの場合を足す。いずれも、幹が枠から 3pt 以内（枠の外側・内側のどちらでも）に来る場合だけ対象で、#558 のファンアウトの規則は変えない。

- ファンイン: 同じポートへ入る、位置の違う 2 本以上の折れる線。
- 折り返し: 相手の端と反対を向くポートへ入る 1 本の線。幹の置き場がほかにない。

幹の位置は、ポートから `need - clearance`（矢じりの長さ + 角）の所にあり、枠までの余白が `need - 2 × clearance` より大きい（幹が枠から 3pt 以内）ときだけ余白を広げる。それより枠から遠い幹は、すでに 3pt 以上離れているので広げない（embedding-gemma の再現図など、固定された図は変わらない）。

## 結果

- 例・ギャラリー・Skill のレイアウト・固定した再現図の出力は変わらない（SVG を変更前後で比較した）。
- 期待値を更新したテスト: #109 の serving-architecture（研究の図）で、`api` グループの枠沿いの指摘が消え、`edges[16]` が枠上（0.16mm）から枠沿い（0.52mm）になり、交点が 129.0mm から 130.8mm に動く（`proximity.integration.test.ts`、`crossings.test.ts`）。
- 1 の幹は枠の内側 3pt、2 の線は段差のない 1 本の折り返しになる。
