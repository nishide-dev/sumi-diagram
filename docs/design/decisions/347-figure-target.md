# #347 置き場所の予算と最終サイズによる縮小の判断

> 添字の判定は [#356](356-script-min-font.md) で見直した（`minFontSize` 明示時は縮小なしでも warning）。

## 背景

[#345 の調査](https://github.com/nishide-dev/sumi-diagram/pull/346) は、置き場所の
幅だけでなく、高さの予算・媒体ごとの最小文字・予約する紙面を比べる必要を示した。
90%という縮尺の閾値は、5ptを許す媒体と9ptを要求する媒体の違いを扱えない。
ユーザー判断（2026-11-04、#347）により、最小文字の引き下げも4.5ptまで許す。

## 決定

- `figure.target` は strict な任意オブジェクト。各値は単位付きの長さで入力し、
  量子化せず pt に正規化する。IR に任意のまま保持する。配置・描画・フォント・
  既存 Profile のページ上限には適用せず、幾何 lint の判断材料だけにする。
- `height` は正の**予算**。margin 込みの印刷高さが超えたら
  `geometry/exceeds-target-height`（warning）をそのフィールドの位置で報告する。
  縦投影の union（最上位本体/ラベル/badge）、隙間、外周/その他の突出、最大3要素の
  高さと canvas 上端からの位置を示す。入れ子や重なりを足し上げて二重計上しない。
- `minFontSize` は4.5pt以上。通常/縮小時両方の Profile の下限を上書きする。
  明示時は描画前の `profile/font-too-small` をスキップする。これで Profile より
  小さい設計も描画でき、引き上げも最終サイズの `geometry/text-too-small` error
  で評価できる。通常ラベル・sublabel・HTML は同じ下限。HTML は viewport→配置→
  印刷の縮尺を使う。数式の添字は従来どおり error 対象外で、縮小時だけ info。
  検証には `render` / `lint --geometry` を使う（通常の構造 lint だけでは不十分）。
- `minLineWidth` も採用する。正の長さ。最終的な図の枠/辺の線幅が下回ると
  `geometry/line-too-thin`（warning）を要素の位置で報告する。Profile には新たな
  線幅の既定を設けない。不可視/幅0の線・文字だけの要素は除く。IR で管理しない
  image/icon/HTML の内部の線は測らない。画像の frame も今回の検査の対象外。
  レンダラーが線を描かない要素（junction の点、トークン区切りの枠、アイコンだけの
  label 枠）も、IR の strokeWidth に関わらず除く。
  JSON Schema では refine が失われるため、正の長さ（0 の全表記を除外）と
  minFontSize の4.5pt下限（pt/mm/cm/in 各単位）を入力側の pattern で表し、
  実行時の refine と二重に保つ。
- `geometry/heavy-scaling` は縮小した図で最小の最終文字が下限の120%以下なら info。
  **20%の余裕**は規定ではなく、候補を再確認するための目安。最小値には添字と
  配置後の HTML も含めるので、85%で4.2ptの添字になる図も知らせる。文字がない図は
  対象外。最終サイズ・下限に対する比・ptでの余裕・縮尺を報告し、自然幅の内訳は
  維持する。本文の error と添字の info は独立。
- 明示的な target（空オブジェクトも含む）でのみ `geometry/placement-usage`（info）。
  Profile 最大幅 × 印刷高さ（margin 込み）の予約面積 mm²、実幅/最大幅、任意の
  高さ予算比を1件で示す。1段なら段幅、全幅なら全幅を既存 Profile が表す。
  縦横比への評価ではなく、同じ置き場所の候補比較用の量とする。
- `sumi catalog` の v1 に追加的な `targets` section を設け、入力スキーマと意味を
  human/JSON 両方で公開する。JSON Schema は同じ Zod から生成する。

## 採らなかった案

- 媒体ごとの Profile の大量追加: 幅・媒体・予算の組み合わせが増える。今回は図単位。
- 高さに合わせた自動縮小、縦横比そのものへの診断: 高さは配置と紙面の交換関係であり、
  内容によって自然な形が違う。幅だけの fit の契約を維持する。
- 線幅の一律の既定: 媒体の要件が違う。宣言がある場合だけ検査する。
- target を書かない図への予約面積 info: 既存診断を不要に増やさない。
- 添字を本文と同じ error にする: 組版上の小さい添字を許してきた契約を維持する。

## 互換性と検証

target がない図の描画出力・診断は heavy-scaling の判定/文言以外は維持する。
既存162 YAML × 自身のテーマと組み込み5テーマ（972試行）を変更前後に描画し、
SVG/PDF/画像方式PPTX/D2 の sha256 と診断を比較する。描画不能の負例や歴史的な
研究用入力も除外せず、失敗の診断を比較する。詳細結果は PR 本文に記録する。
新しい target は入力ハッシュ以外の描画を変えないことも回帰検査する。
golden とギャラリーは定められた生成コマンドでのみ更新する。
