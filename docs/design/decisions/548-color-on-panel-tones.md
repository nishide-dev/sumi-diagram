# #548 `geometry/color-on-panel` を tone 間でそろえる

## 背景

#539 で、`geometry/color-on-panel` が緑のパネルでは出て、同じ使い方の青のパネルでは出なかった。再現: `theme: sumi` で、`tone: gray`・`variant: filled` のグループ（パネル）に、同じ tone の `filled` の箱を 3 つ置く。tone を変えて lint すると、red・orange・yellow・green では出て、blue・purple・pink では出なかった。gray は出ない（パネルと同じ色）。

比べていた値は、要素自身の色（`filled` は塗り、`tinted` は線）の OKLCH 彩度と、固定のしきい値 `COLORED_CHROMA` = 0.025 だった。sumi の淡い塗りの彩度は gray 0.022、red 0.028、orange 0.029、yellow 0.040、green 0.029、blue 0.012、purple 0.019、pink 0.020 で、しきい値は red と gray の間にあるため、blue・purple・pink が「無彩色」扱いになった。しきい値の境目ではなく、パレットの設計（青・紫・桃は彩度を落とし、黄・橙・緑は暖かいパネルと同じ色相に寄せている）が原因である。

## 決定

- 「色付き」の判定を、彩度の絶対値だけでなく、**パネルの色との差**でも行う。彩度が 0.025 以上、または OKLab の a/b 平面でのパネルの色との距離（色相と彩度の差。明るさは含めない）が 0.02 以上なら色付き。定数は `COLORED_FROM_PANEL`。
- 同じ段の淡い塗りでは、sumi のパネル（`#e1dece`）に対する距離は blue 0.028、purple 0.039、pink 0.032 で、gray 0。これで gray 以外の全 tone がそろって報告され、gray は報告されない。
- 「パネルと競う」という規則の意味に沿う: 競うのは、パネルと見分けがつく色のとき。パネルとほぼ同じ色（gray）は競わない。

## 採らなかった案

- しきい値を 0.012 以下に下げる: 無彩色のパネルを持つほかのテーマで、ごく淡い灰色の変種まで拾う。
- 違う理由を文書にするだけ: blue が gray 同然の彩度なのは意図だが、パネルとの見分けは付く。そのため、図を見る人にとっては緑と同じく「色が競う」。

## 互換性

info の診断であり、図の出力（SVG）は変わらない。パネルを持ち、gray 以外の淡い tone の要素が 3 つ以上載る図で、新たに出ることがある。
