# 512: 枠からの幹の間隔と、同じ側の入れ子のスキップの通り道

## 問題

#531 の後も、次の 2 つが再現した（#538 の再計測・#539 のレイアウト作成）。

1. 1 つの箱からグループ内の 3 つの箱へのファンアウトの幹が、グループの枠から約 1.75pt（線と線の間 0.26mm）しかなく、枠の一部に見える（`geometry/edge-near-border`）。
2. 同じ側の入れ子のスキップ接続（`fromAnchor: east` / `toAnchor: east`、残差の積み重ね）が、ほぼ同じ縦線に重なる。`residual-skip-stack` は `route: curve` で回避していた。

## 原因

1. グループの余白（`padding.ts`）は「両端が同じグループの中にある」辺の矢じり手前（スタブ + 角 + 余白 3pt）しか確保しない。外の箱から入る線は対象外で、幹が枠から 3.5 単位に曲がる。
2. 経路探索の格子には、箱の脇に「箱 + 矢じりの余白」の 1 本の縦線しかない。2 本目以降の同じ側のスキップは、重ね（コスト 4000）か大きな迂回しか選べず、重なりを避けると別の格子線が 1 単位隣に選ばれることもある。

## 決定

- `arrowheadPaddingDeficits`: グループ外の同じポートから同じグループの複数のメンバー（位置がそろっていない）に入る線（ファンアウト・ファンイン）も、幹が枠から 3pt 離れる余白を確保する。単独の線と、まっすぐ入る線は対象外（余白は変わらない）。
- ルーター: 両端が同じ側に出る線に、箱の脇の格子線を 3 本追加する（線の間隔は 1.5pt の隙間 + 線幅）。
- `separateSameSideRuns`（`parallel.ts`）: 同じ側の C 字の経路で、縦線の区間が 3mm 以上重なり、線の間隔が足りないものを、区間の短い順に箱に近い側から別の通り道に置く。入れ子の線は交差しない。箱・グループの枠・他の線に新たに触れる移動は取りやめる。

## 結果

- 例・ギャラリーの再現図の出力は変わらない。スキルのレイアウト `encoder-decoder` と `pipeline-branch-merge` の SVG が、グループの余白の分だけ変わる。
- `route: curve` の `residual-skip-stack` は変更なし。

## 残り

- 3 本を超える同じ側のスキップは、格子線が足りない分を後処理が補う。
