# #420 TriCL の概要図を密度の基準として再現する

- **背景**: 論文の図の試行（#412）は、部品は足りたが、図が疎で（余白が多く、要素が小さく、文字が多い）論文に載せる品質に届かなかった。TriCL（arXiv:2206.04739）の Figure 1 は、横長の図に、ハイパーグラフ、2 つの拡張ビュー、共有エンコーダ、2 種類の射影ヘッド、出力、3 種類の対照を少ない文字で密に並べている。これを基準として再現し、構成・大きさ・間隔を元の図と並べて測り、足りない機能を記録する。
- **決定**:
  - 例 `tricl`（`paper` / `paper-double`。色も元の図に忠実に再現する: 白いカードと黒い枠（`groupFill` / `groupStroke`）、灰色 `#e6e6e6` 相当のパネル、対照の blue `#1942f3` / red `#d0352b` / 濃い緑 `#296218` を元の画像から取り、`themeOverrides.tones` に書く。特徴ベクトルとマスクの点は gray の色上書きで黒・灰色。ビューからエンコーダへの太い矢印は `emphasis` + `tone: gray` の黒い辺）を `examples/` と `skills/sumi/examples/` に加える。ルートは 1 つの `place`（単位 1pt、元の画像 1px を 0.3pt）で、全要素を測った中心に置く。ハイパーグラフのカードは各自の `place` を持つグループで、頂点（`ellipse` と特徴ベクトルの `glyphs`）、破線の `sets`（`shape: hull`）、マスクされた頂点（塗りの円）を並べる。
  - 3 枚の灰色のパネル（エンコーダ・2 つの射影ヘッド）は、`shape: rect` の `sets` にした。集合は配置に場所を取らないので、パネルの中の箱を元の図の y に置け、パネルをまたぐ P・Q・Z・Y の線が直線になる。グループにすると、積み重ねの余白がパネルごとに決まり、箱の y が外の Z・Y とずれて線が折れた（測ると 2〜3pt）。
  - 上部の凡例は、標本の線の真ん中に印（円・四角・菱形）がある。`legend` 部品にはこれがないので、グループの中の `row` に、隠れた接合点 2 つと印のノードを並べ、印から両端へ破線の矢印を引いた。左の「マスク」の凡例は `legend` の `glyph` と `node` の標本をそのまま使う。
  - 点線がないので、対照の線は `variant: dashed` の曲線（`route: curve`）とした。2 本の曲線が印のノードの north / south アンカーでつながり、印を通る 1 本の弧に見える。
  - 小さな変更を 1 つ: `lint/empty-label` が、`glyphs` を持つノードと、明示した幅と高さ（円と正方形は幅のみ）がすべて 10pt 以下の、`box` 以外のノードを、空のラベルとして警告しないようにした（小さな `box` は空のセルとして警告したままにする。手書きのセルを `matrix` / `tokens` と比べる既存のテストがこれに依る）。頂点の点や印は文字を持てない絵であり、例が `sumi lint` で警告 40 件になるのを避ける。出力（SVG・PDF・PPTX）は変わらない。
  - 足りない機能は PR の「不足している機能」に記録した（`\mathcal` / `\mathbf`、点線、斜線の塗り、中間の印つきの凡例、文字サイズ、グループの余白、辺ラベルの背景など）。別のイシューに分ける。
  - ドキュメントの小さな誤りを直した: `glyphs[].size` は倍率ではなく長さ（`2.5pt`）。
- **採らなかった案**:
  - 灰色のパネルをグループにする案: 上記の理由で線が折れる。`place` の座標は `figure.layout.align` で動かせない（ドキュメントの記載。試していない）。
  - 文字を大きくするために箱を小さくする案: 元の図は文字が箱に対して約 18% 大きいが、箱を小さくすると幅の上限（180mm）の中で図が小さくなり、「要素が小さい」ことの再現になる。文字サイズの指定は大きな機能なので、この PR では扱わない。
  - 凡例を `legend` のまま、中間の印を `node` の標本で近似する案: 印が線の端に付き、元の図と形が違う。
- **互換性**: Sumi 本体の出力は変わらない。`lint/empty-label` の変更は lint の結果だけで、リポジトリの全 `*.sumi.yaml`（`research/` と非公開の図を除く）の `sumi lint` を変更の前後で比べ、差がないことを確かめた。例のゴールデンは `bun run gallery` と `SUMI_UPDATE_GOLDEN=1 CI=1 bun run test src/render/pdf src/render/pptx src/render/assets.integration.test.ts` で再生成した。
